## Follow-up (not changed here)

1. **`dnsutils` install fails on a stale apt index.** The first baseline run, on the unrefreshed golden image (apt lists from 2026-07), failed before the block at `FreeIPA DNS client — install dig (Debian)`: `E: Failed to fetch …/dnsutils_9.18.39-0ubuntu0.24.04.5_all.deb  404  Not Found`. The task uses plain `ansible.builtin.apt` rather than the apt framework (`tasks/apt-package-install.yml`, which handles stale indexes). The image already had `/usr/bin/dig` from `bind9-dnsutils`; `dnsutils` is only a transitional package. The snapshot used above ran `apt-get update` first to get past this.
2. **After the rollback, DNS still points at the failing server on Ubuntu.** The rescue only restores `/etc/resolv.conf`. The systemd-resolved drop-in (`DNS=192.0.2.53`) and `/etc/netplan/99-pilot-freeipa-dns-client.yaml` (DHCP DNS disabled) stay in place. The restored file is the stub (`127.0.0.53`), so lookups still go through systemd-resolved to 192.0.2.53: `getent hosts archive.ubuntu.com` timed out (rc=124) after the rollback on both revisions. The restore also replaces the symlink with a regular file. The backup is taken after systemd-resolved has already been restarted with the drop-in, so it holds `search ipa.pilot.internal` instead of the original `search .`. Name resolution comes back only after a re-run with correct servers (the forward fix the runbook describes) or after removing the two drop-ins.

## Redaction

No secrets were involved; the playbook reads no vault. The scenario driver was a per-run file outside the repository.

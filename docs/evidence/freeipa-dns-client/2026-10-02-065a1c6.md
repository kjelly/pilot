# freeipa-dns-client: C7 reads option numbers the way glibc does — 2026-10-02

Candidate `065a1c6` changes how the C7 command in `docs/verification/freeipa-dns-client.md` reads numbers (PR #37 review of `c350dce`). The previous C7 (`6224982`) used awk's `int()`, which reads `10e-1` as the float 1. So `options timeout:10e-1 attempts:2` passed, although glibc runs with 10 seconds, and so did `timeout:1 attempts:20e-1`, although glibc makes 5 attempts. glibc 2.39's `res_setoptions()` reads the value with `strtol(…, 10)` and caps it at 30 (timeout) and 5 (attempts). C7 now does the same:

- It takes the leading decimal integer, with an optional sign.
- If the value is empty, it reads the next field, because `strtol` skips the blank.
- It applies the same caps.
- A value with more than nine significant digits, which glibc wraps around, prints `invalid` and fails.

The playbooks are unchanged.

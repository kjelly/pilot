## Development run (before the candidate)

On a standalone AlmaLinux 9.8 VM, with explicit `freeipa_dns_client_servers` and `freeipa_server_fqdn=isc.org` so the functional check could pass without FreeIPA:

- With two servers, the options were set; rerun `changed=0`. With one server they were cleared; rerun `changed=0`. Two servers again set them again.
- A run with an unreachable server failed, and the rescue reported "connection 'System eth0' DNS settings restored". But the stored `ipv4.dns-options` now contained backslashes (plain `-g` showed `timeout\\\:1,attempts\\\:2`), and NetworkManager no longer wrote the `options` line.
- Cause: plain `nmcli -g ipv4.dns-options` prints `timeout\:1,attempts\:2` (colons escaped), and writing that back stores the backslashes. `nmcli --escape no -g` prints `timeout:1,attempts:2`, and that round trip restores the value. The snapshot now reads every field with `--escape no`.
- The same scenario after the fix: the rescue restored `timeout:1,attempts:2`, and the options line was back.

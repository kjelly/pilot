## Real captures used by the change

- `timeout --kill-after=30 20 apt-get update` on a stalled index, as the command module reports it: `rc=124`, stdout and stderr empty.
- The KILL case, from coreutils on the controller through Python's subprocess (`TestAptTimeoutExitCodes`): `-9`. `timeout` KILLs its own process group, so there is no exit status 137 unless a shell sits in between.
- `apt-get update` with every index answering 503: `rc=0`. stdout has `Err:N … InRelease` followed by `  503  Service Unavailable [IP: …]`. stderr has four `W: Failed to fetch http://…/dists/<suite>/InRelease  503  Service Unavailable [IP: …]` lines and `W: Some index files failed to download. They have been ignored, or old ones used instead.`, with no `E:` line.

## Follow-up (not changed here)

`apt-classify-failure.yml` only emits errors for known patterns or `E:` lines, so the 503 capture above classifies as zero errors, and the refresh reads as `healthy`. With this change the outcome is still correct: on the stale path the re-probe decides, and on the candidate-missing path the candidate re-check decides. Only the reported `refresh_result` is misleading. Classifying `W: Failed to fetch <url>  <3-digit status>` would fix the label.

## Redaction

No secrets were involved. The test proxy, the throwaway playbook and the scenario driver were per-run files outside the repository.

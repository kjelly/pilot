This record follows `2026-10-14-01a64f4.md`. A review of PR #92's head `44e2d20` found these problems:

- **[P3] A working replica was dropped.** `tasks/freeipa-dns-providers-live.yml` kept a replica only when its inventory FQDN was in FreeIPA's NS records. A replica installed under another name was left out, even though it answers for the zone.
- **[P3] One lost packet decided.** The dig probes used `+tries=1`, and "no FreeIPA server answered" was not reported.
- **[P3] The resolver gate failed on anything.** Any written nameserver that did not answer an A record failed the run:
  - a registered server under maintenance;
  - a dns tier host that was down;
  - an explicit entry;
  - an IPv6-only answer.

  An explicit `127.0.0.1` was asked with `+norec`.
- **[P3] Empty forwarders did not converge.** On an existing realm, an explicitly empty list skipped `ipa dnsconfig-mod`, and the old global forwarders stayed.
- **[P3] Address check.** The address check was a regular expression. `"1.1.1.1 port 53"` was refused, although FreeIPA accepts that form.
- **[P3] Visibility.** The dns summary did not show which FreeIPA servers the stubs use.

## Changes in `09ded7e`

- **A replica is kept when it answers the zone itself.**
  - `tasks/freeipa-dns-providers-live.yml` keeps a candidate whose own `+norec` NS answer is NOERROR with `aa`, whatever its inventory name.
  - It also keeps a candidate whose FQDN is in FreeIPA's NS records.
  - Probes use `+time=2 +tries=2`.
  - A message says when no FreeIPA server answered.
  - The WARNING lists four remedies: promote the replica, set `freeipa_replica_fqdn` to FreeIPA's name, start named, or set `freeipa_setup_dns: false`.
  - `pilot_diagnose_dns_architecture` follows the same rule, and its provider probe also uses `+tries=2`.
- **The resolver check blocks only what must be blocked.** The new `tasks/freeipa-dns-client-nameserver-check.yml` asks each nameserver for the FreeIPA FQDN, both A and AAAA. It fails only when:
  - a server answers without an address;
  - a FreeIPA server that FreeIPA does not list does not answer;
  - no server answers with an address.

  A server that is down now gets a WARNING with a remedy for its role, and stays in the list. Only FreeIPA DNS servers are asked with `+norec`. The dns tier's G5 still fails closed when a listed FreeIPA server does not answer. That behaviour is unchanged and is now documented.
- **Forwarders converge.** Every run of `freeipa-server-apply.yml` sets two lists to the configured forwarders:
  - the realm's global forwarders, with `ipa dnsconfig-mod`;
  - the primary's own forwarders, with `ipa dnsserver-mod <fqdn>`. FreeIPA stores the install-time `--forwarder` there, and named prefers it over the global list.

  An explicitly empty list clears both. `freeipa-server-replica-apply.yml` does the same for a replica's own forwarders; empty is the default there, and the replica then uses the global list.

  **This is a breaking change.** It is recorded in `freeipa-server.md` v1.9, `freeipa-server-replica.md` v1.2 and `group_vars/freeipa.example.yml`.
- **The address check.** Python's `ipaddress` checks each forwarder on the controller, and Go's `net/netip` in `internal/diagnose`.
  - `"<address> port <n>"` is accepted.
  - An unspecified or multicast address, an address with a zone, and a port outside 1–65535 are refused.
  - The installers take plain addresses only. When a run would call `ipa-server-install`, `ipa-replica-install` or `ipa-dns-install` with a port form, a `pre_tasks` gate stops it before any change.
- **Visibility.** `DNS — summary: FreeIPA servers the stubs use` prints the effective servers, the ones left out, and who answered.

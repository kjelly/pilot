# Diagnose wording, NS-only self answer, IPv4-mapped forwarders — candidate `5750f2a` (2026-10-15)

This record follows `2026-10-15-09ded7e.md`, which has the control comparisons against `44e2d20`. An adversarial review of `09ded7e` found:

- **[P2] Diagnose still said per-server forwarders are not pilot-managed.** `09ded7e` makes both FreeIPA playbooks set each server's own forwarders with `ipa dnsserver-mod` on every apply. Three places still said the opposite:
  - `pilot_diagnose_dns_architecture`'s mismatch detail;
  - its `NotManaged` list;
  - `docs/runbooks/dns-architecture-diagnose.md`.

  An operator who changed `freeipa_dns_forwarders` would be told the setting is unmanaged, when the fix is to re-apply.
- **[P3] Go and Ansible disagreed on a replica's own answer.** `DNSArchUnregisteredReplicas` accepted the replica's own SOA answer as well as its NS answer. `tasks/freeipa-dns-providers-live.yml` asks only NS.
- **[P3] IPv4-mapped addresses.** `::ffff:0.0.0.0` passed Go's check. The playbook refused it only because the controller runs Python 3.13; older Pythons accept it.
- **[P3] Misleading WARNING.** The resolver WARNING said "a FreeIPA DNS server FreeIPA answers for" even when no FreeIPA server had answered.

## Changes in `5750f2a`

- **Diagnose wording.** The mismatch detail now says to re-apply `freeipa-server-apply.yml` or `freeipa-server-replica-apply.yml`, and the `NotManaged` entry is removed. The subject is now `FreeIPA <host> server forwarders (ipa dnsserver-mod)`, and the runbook paragraph is rewritten.
- **NS only.** `DNSArchUnregisteredReplicas` uses the replica's own NS answer only, as the playbook does.
- **IPv4-mapped addresses.** An IPv4-mapped address is judged as the IPv4 address it maps: Go uses `netip`'s `Unmap`, and the playbook uses Python's `ipv4_mapped`. `TestNormalizeForwardersMatchesPlaybookGate` gained two cases, `::ffff:0.0.0.0` and `::ffff:224.0.0.1`. On `09ded7e`, Go accepted the first: `want a failure; … go err=<nil>`.
- **WARNING text.** The WARNING for a FreeIPA server that does not answer now says either "FreeIPA lists it as a DNS server", or "No FreeIPA server answered, so whether FreeIPA lists it is unknown". `TestRegression_ResolverNameserverCheck` checks both.

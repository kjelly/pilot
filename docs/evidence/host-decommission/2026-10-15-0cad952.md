# Decommission finds the rules naming a host, and ignores tombstones (2026-10-15)

Issues #104 and #108. Spec: `docs/verification/host-decommission.md` (HD10–HD12); code: `internal/decommission/providers/freeipa_client.go`; queries: `playbooks/apply/freeipa-identity-apply.yml` (`freeipa_host_absent_inspect` tasks); tests: `internal/decommission/providers/freeipa_client_test.go`, `internal/spec/freeipa_identity_ipa_failures_regression_test.go`, `internal/spec/ipa_cli_options_regression_test.go`.

Two defects made decommission checks pass while residue remained:

- **#104**: Verify's HBAC and sudo direct-reference queries used `ipa hbacrule-find --host=<fqdn>` / `sudorule-find --host=<fqdn>`. Neither command has a host filter. optparse reads `--host=` as the unique prefix of `--hostcat`, so the queries never matched and both checks always passed.
- **#108**: the queries run with `--tags freeipa_host_absent_inspect`, which also prints a `HOST_INSPECT` block for every `state: absent` roster host, and retired hosts stay there as tombstones. The provider read the whole stdout, so another host's "host not found" stood for the target. As a result, the central converge step looked done (skipping host-del), Plan skipped the HD12 unknown-service check, and Verify passed `host_object`/`host_dns`.

## 2. CLI-wiring gap confirmed, then fixed (commit `1b0acaf`)

Before any code change, `decommission.PlanInput.Providers` was never populated by
`cmd/pilot/cmd/host_decommission.go` — every `pilot host decommission plan` for a
freeipa-client host came back `external_state_unsupported`, no matter what roster/roles
were given, exactly as Phase 3a's own commit message predicted. Added
`buildHostDecommissionProviders` (constructs a real `*ansible.Runner`-backed
`FreeIPAClientProvider`, resolving `inventory.yml` via the existing
`autoRegenerateInventoryFromHosts` and the host's own `freeipa_roster_file` extra var),
wired into `plan`/`apply`/`resume`'s `PlanInput`/`PlanInputForFreshness`. Unit tests:
`TestBuildHostDecommissionProviders_RegistersFreeIPAClientForMatchingHost`,
`TestBuildHostDecommissionProviders_UnknownHostReturnsEmptyRegistry` (both new, both
green — `go test ./cmd/pilot/cmd/... -run TestBuildHostDecommissionProviders -v`).

Also found and fixed at this stage: nothing in `internal/decommission` ever actually
*executed* a provider's planned steps or collected real `Verify()` results before
`Finalize` — `apply` would have silently removed the host from `hosts.yml` without ever
running `ipa-client-install --uninstall` or the central roster/host-del convergence.
Added `internal/decommission/execute.go`'s `Apply()` (the missing orchestrator: freshness
check → execute every component's planned steps via the existing, already-tested
`Executor`/`StepExecutor` machinery → collect real `Verify()` results → `Finalize`) and
`providers.StepExecutor`/`StepRunner` + `FreeIPAClientProvider.ExecutorForStep` (real
Inspect/Execute pairs for the uninstall, roster-absent, and identity-apply-converge
steps).

## 9. Real bugs found and fixed this round (not guessable from source/fixtures alone)

All five are committed as `3b4ef4d` (plus the CLI-wiring gap itself as `1b0acaf`); see
that commit's message for full detail. Summary:

1. **FQDN precedence bug** (`internal/decommission/planner.go`,
   `internal/decommission/execute.go`): `firstNonEmpty(host.AnsibleHost, host.Name)`
   silently preferred the SSH connection IP over the workspace's own host identity —
   every FreeIPA operation targeted `192.168.122.3` instead of
   `hd-client1.ipa.pilot.internal`. Fixed via `providerFQDN()` (Name first).
2. **Apply()/Finalize() freshness interaction** (`internal/decommission/execute.go`):
   central-cleanup steps intentionally mutate the roster; `Finalize`'s own freshness
   re-check compared against the plan's pre-cleanup hash, permanently reporting
   `plan_stale` after real cleanup ran. Fixed by re-deriving and persisting the plan
   after cleanup succeeds, before calling `Finalize`.
3. **stderr vs stdout** (`playbooks/apply/freeipa-identity-apply.yml`): `ipa host-show` on
   an absent host prints "not found" to stderr, not stdout; the debug print only
   forwarded stdout, so `Verify()`'s `notFoundPattern` never matched a genuinely-absent
   host, reporting a false `active_residue`. Fixed by concatenating stderr.
4. **Wrong FreeIPA raw attribute names**
   (`internal/decommission/providers/freeipa_client.go`,
   `playbooks/apply/freeipa-identity-apply.yml`): `managedby_service:`/
   `memberof_hostgroup:`/`memberof_netgroup:` never existed in real `ipa host-show --all
   --raw` output — this permanently disabled HD11's residual-membership gate and HD12's
   unknown-service-principal gate, in both the Go provider and the mutating ansible
   safety gates, since day one of Phase 3a. Fixed by switching to plain (non-raw)
   `host-show` (`Member of host-groups:`/`Member of netgroups:`) plus a separate `ipa
   service-find --man-by-hosts=<fqdn>` query for services. Also fixed a second, related
   gap: the host_object query was gated on the roster's `freeipa_absent_hosts` list
   (empty at normal plan time, since the roster still shows `state: present`) — added a
   query-kind-driven task pair keyed on `pilot_decommission_target_fqdn` instead.
5. **ansible debug JSON-escaping** (`internal/decommission/providers/freeipa_client.go`):
   `ansible.builtin.debug` renders a string `msg:` with literal two-character `\n` escape
   text, not real newline bytes, in its default console callback (confirmed by capturing
   raw `ansible-playbook` stdout to a file and inspecting it byte-for-byte with `cat -A`).
   Every field-extraction regex here was anchored with `^`/`(?m)$`, which can only match
   at a real line boundary — against this console text none of them ever matched
   anything, so `Verify()`/`discoverUnknownServicePrincipals` silently reported "nothing
   found" regardless of live state. Fixed via a shared `fieldPattern()` that stops a match
   at a literal `\n`, a real newline, or end of string.

Bugs 4 and 5 are why HD12 (and, less severely, HD11's hostgroup/netgroup checks) could
never have actually fired before this round even though the Go-level fixture tests all
passed — the fixtures encoded the same wrong assumptions about real `ipa`/ansible output
shape that the implementation made. Existing fixture tests
(`internal/decommission/providers/freeipa_client_test.go`) and one Ansible-structure
regression test (`internal/spec/freeipa_identity_host_absent_regression_test.go`) were
updated to match the corrected, real output shapes rather than weakened.

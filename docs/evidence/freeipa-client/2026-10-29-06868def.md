## Mutation check: base commit on the same drifted VM

Same drift as S1. First observation (SSSD running): the base playbook's `--check` passed, because SSSD's krb5 locator plugin hands the KDC address to `kinit` from `/var/lib/sss/pubconf/kdcinfo.*` and no name lookup is needed. Without the locator (`sssd` stopped, which also removed the `kdcinfo` file; `kinit admin@IPA.PILOT.INTERNAL` then printed `Cannot contact any KDC for realm 'IPA.PILOT.INTERNAL' while getting initial credentials`), the base `playbooks/` tree at `348c4911`, same command as S1:

```
TASK [FreeIPA host annotations - kinit admin into the dedicated ccache]
fatal: [i168-cli]: FAILED! => {"censored": "the output has been hidden due to the fact that 'no_log: true' was specified for this result", "changed": false}
PLAY RECAP: i168-cli : ok=76 changed=1 failed=1
```

The candidate on the identical state: S1 above (`failed=0`, deferral message), S2 (explicit failure message), S3 (`failed=0` after the pin). Verdict: the base reproduces the censored failure from the issue, the candidate does not. With SSSD running and the same drift, the base preview also printed a "BLOCKED (HOST_ABSENT)" plan for a host object that exists (the FreeIPA read could not reach the server by name) and still passed; the candidate defers instead.

## S4: real kinit failure classes (each from a state, then restored)

The annotations kinit reads `ipa_enroll_password` (defaults to `ipa_admin_password`; `-e` overrides it). The classified message never contains the password or the raw stderr: a count of the throwaway wrong password in the whole run output was 0.

| Case | State | Real `kinit` stderr on the client (manual run, same realm) | Play result (full real apply) |
|---|---|---|---|
| S4a wrong password | `-e ipa_enroll_password=<wrong>` | `kinit: Password incorrect while getting initial credentials` | `failed=1`; `kinit admin@IPA.PILOT.INTERNAL failed on i168-cli: pre-authentication failed: the KDC rejected the admin password (check ipa_enroll_password) (class=preauth_failed, kinit rc=1; the raw kinit output is withheld because the task handles the admin password).` |
| S4a' unknown principal | manual `kinit nobody168@...` | `kinit: Client 'nobody168@IPA.PILOT.INTERNAL' not found in Kerberos database while getting initial credentials` | not run through the play (text matches the `client_not_found` pattern) |
| S4b KDC unreachable, names resolve | `krb5kdc` stopped on the server (no `nft`, `iptables` or `firewalld` on the AlmaLinux image, so a port-88 drop rule was not possible; a closed port, not a dropped one) | `kinit: Cannot contact any KDC for realm 'IPA.PILOT.INTERNAL' while getting initial credentials` | `failed=1`; `... no KDC answered (the KDC names resolve, but the KDC is down, firewalled or on another port) (class=cannot_contact_kdc, kinit rc=1; ...)` |

The FreeIPA KDC on 4.13.4/krb5 1.21.1 says `Password incorrect` for a wrong password (not `Preauthentication failed`), which the preauth pattern covers. An unresolvable KDC name and a closed KDC port print the same `Cannot contact any KDC` text with krb5 1.20.1 on the client; the play separates them with the preflight result (S1/S3 state vs S4b).

**Not captured: S4c clock skew.** The client clock was moved +20 minutes and then +1 day with chrony stopped. Each time `kinit` still reached the KDC and printed `Password incorrect` for the wrong password (and the play passed at +20 minutes): libkrb5 takes the time offset from the KDC's pre-authentication-required reply, so a password `kinit` against this FreeIPA does not fail with `Clock skew too great`. The `clock_skew` pattern therefore remains matched only to the libkrb5 error-table text, not to a live capture.

## Deviations / follow-ups

- **`apt-get update` hung on an earlier attempt.** It stalled on `tx-gw` with a CLOSE-WAIT connection to the host's apt-cacher-ng (`192.168.122.1:3142`). I killed it by hand. The refresh step then still reported `ok`, the install hit `404 Not Found` on stale package URLs, and the run rolled back. The final run needed no intervention. Follow-ups: the refresh `apt-get update` has no timeout, and the install still proceeds after a failed refresh.
- **Re-wire after each rollback failed** with `wiring tx-ipa's /etc/hosts failed (exit=255): ssh: connect to host 192.168.122.2 port 22: No route to host` (it did not wait for SSH). The disk rollbacks themselves completed. The snapshots were taken after `topology up` had already wired `/etc/hosts`, so the next run started from correctly wired disks.
- **The first driver pass's lockout calls never ran.** They exited 2 because the driver exported both `PORTAL_PASSWORD` and `PORTAL_KEY`, and the lockout script refuses that combination. That pass's E2E phases (the `875066d` script) all passed. The formal pass above unsets `PORTAL_PASSWORD` for the lockout suite.
- **The AG71 leak check covers only the run's marker.** The marker is in the transfer file names and in the target commands that touch them. File content is random bytes, and the AG63 commands carry no marker. The inner username cannot be separated from the portal user here, because both are `transportuser`.

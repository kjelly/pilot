## Observations

- Upgrading from a gateway that already records needs
  `pilot_access_gateway_recording_mode` kept; the downgrade guard refuses
  otherwise, without changing anything. The `failure_policy` default changes
  from `best_effort` to `fail_closed`. A rollback must put the static token
  file back on the gateway before the previous gateway playbook runs. All
  three are now in the session store runbook.
- After a rollback the candidate's signing key file stays on the gateway;
  the previous binary does not read it.
- On `34aad5a`, `pilot session` defaults to `/run/pilot/session-store.sock`,
  but the store listens on `/run/pilot-session-store/session-store.sock`;
  this branch's default is the latter. Reading with the previous revision
  needs `--socket`.
- The one-shot `pilot-connect` failure line for an unreachable store carries
  the transport error (store URL, address). The same line was printed
  before the merge: `portal-session` already silences cobra, so #13 does not
  change it.

# Per-host SSH session recording: AG82 refuses before anything changes, and a failed run's restart is not lost — candidate `02acc60` (2026-10-02)

Scope: the PR #19 review of `031bd36`. AG82 refused a bad former token path only after Step 11 and AG81 had replaced the gateway config and the signing key. The replaced config no longer named the custom token. So the corrected retry neither removed the token nor, with config and key unchanged, restarted the gateway, which kept running its old settings. A failure anywhere between Step 11 and the restart had the same effect on the restart. The candidate:

- **Checks before Step 11.** AG82's reads, path checks and file-type probe run before Step 11 and AG81. A refusal says "Nothing was changed".
- **A pending list kept across runs.** The former token paths found are recorded in `/etc/pilot/session-store-legacy-token-files.pending`, and later runs read the list back. The files are removed, with the normalization and inode checks, only after the new gateway passed the Step 17 health check. The list is deleted then.
- **An activation marker.** `/run/pilot-access-gateway.apply-pending` is written before Step 11 and removed after the service restart. While it exists, the socket and the service are restarted.
- **Spec.** AG82 also requires that no pending list is left. The new AG97 requires that a running gateway service and socket started no earlier than their config, key, binary and unit files were last written. It reads the start with `systemctl --timestamp=unix`.

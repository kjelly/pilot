## What the merge with main changed

This branch and `main` fixed three of the same problems independently. The
merge keeps `main`'s version, and this branch's commits for them are dead code
paths now:

| Problem | This branch | Kept from `main` |
|---|---|---|
| Group membership read from the SSSD-cached member list | `682f0f8` | `identity.PeerInGroup` (kernel credentials of the peer) |
| Stale apt index on fresh images; `apt-get update` without a time bound | `f3cd0c6`, `bded49e`, spec rows `8435a9b` | the `--download-only` stale probe, the `timeout`-bounded refresh and `main`'s `docs/verification/apt-repository-tolerance.md` |
| `freeipa-server` installer directories re-owned on re-apply | — | `main`'s `freeipa-server-apply.yml` |

Design integration:

- `authorizeConnect` is the single HBAC ∩ scope decision for connect,
  transport and host keys. It now also resolves the target's recording policy
  (host override > gateway default > built-in `metadata`) and denies an
  invalid or unreadable policy before the transport gate runs.
- D8 (transport only in `""`/`metadata`) reads that per-host effective mode.
- The static store bearer token is gone. Terminal recording always goes to
  `pilot-session-store` with per-session PIT1 tokens. `main`'s local FileSink
  recording is removed, so the transport topology gained a store node and
  AG69's second half checks the store's index instead of a local file.
- Variables follow `main`'s `pilot_access_gateway_recording_*` names. The mode
  has no default (unset means built-in `metadata`), `failure_policy` defaults
  to `fail_closed`, and the AG60 downgrade guard
  (`pilot_access_gateway_recording_allow_downgrade`) is kept.
- `docs/verification/pilot-access-gateway.md`: the transport rows AG41–AG73
  keep their numbers; the per-host rows are renumbered AG81–AG96 (they were
  AG42–AG57); the former AG41 is merged into AG41.
- PR #10 (`fcd3c03`) conflicted in two places: `main`'s empty include-tags
  allowlist was taken, and `docs/verification/freeipa-client.md` got both
  changelog rows (this branch v1.9, `main` v1.10).

## L13 — fail_closed mid-session, live on the merged candidate

Gateway in `terminal_output`, `failure_policy fail_closed`, `failure_grace 10s`.
A one-shot `pilot-connect` to `mx-target` ran
`while :; do echo TICK-$(date +%s.%N); sleep 0.2; done`. `iptables` then dropped
tcp/8443 on `mx-store`.

| Observation | Value |
|---|---|
| Port dropped | 08:32:18.44Z |
| `recording_failed` | 08:32:30.69Z, `sink made no progress for >= 10s` |
| Target output | the last tick printed at 08:32:30.58Z (74 ticks): the target session ended at the trip |
| What the user saw | `pilot-session: session ended: recording could not be saved: sessionrecording: sink failing, fail_closed policy terminating session`; ssh exit 1 |
| Gateway audit, in order | `gateway_authorize_allowed`, `target_connect_started`, `recording_started`, `recording_failed`, `recording_gap` (`drain cancelled: lost 54 event(s)`), `recording_failed` (finish timed out), `session_ended` **`recording failed closed`** |
| Store | `complete=0`, 21 events |

The port was restored afterwards. Before `b436d4f`, `Run` could return `nil`
here: the user would then not see that the recording could not be saved, and
`session_ended` would not say `recording failed closed`.

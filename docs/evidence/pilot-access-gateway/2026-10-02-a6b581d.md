## Found while scanning for the same class, not changed

The gates in front of ForceCommand do not carry its tags, on `main` as here:
- gateway Step 18 "verify configured pilot-target-<scope> exists" (`AG_service`, `AG12`) runs before Step 19 installs the drop-in (`AG_forcecommand`, `AG43`);
- Directory Step 17's health gate (`AD_service`) runs before Step 18 (`AD_forcecommand`, `AD18`).

So `--tags AG43` or `--tags AD18` with ForceCommand enabled skips the check. Changing it needs a ForceCommand run on a real gateway, which the access-gateway spec gates behind explicit approval, so it is left for a separate change.

# audit-log-forwarding C20 distro-policy rewrite (PR #188: Step 1d preflight, Step 5a-5e) — candidate `c97caf38cb06`

Scope: PR #188 replaces the `lineinfile` edit of the distro's `/etc/logrotate.d/rsyslog` with `files/logrotate-drop-path.awk` (Step 5b), writes the result with `copy` + `validate` (Step 5c), removes the file only when nothing but blanks and comments is left (Step 5d), and runs the same computation and logrotate's own check once before the play's first config write (Step 1d). Reported incident: a policy that declares `/var/log/syslog` alone in its stanza made the old edit leave a stanza without a filename, `logrotate` rejected the file, and rotation stopped. This record covers the TCP chain (spec `docs/verification/audit-log-forwarding.md`, 22 rows) on Ubuntu 24.04 and AlmaLinux 9, plus the edge paths of the rewrite. RELP/mTLS, high-volume, rotation-under-load and decommission were not rerun; their last run is `docs/evidence/siem-relp-mtls/2026-10-20-34cfabe-review.md`.

## Not covered

- The lone-stanza layout was induced with a fixture. No supported image ships it: the Ubuntu 20.04 default policy (rsyslog 8.2001.0-1ubuntu1.3) does, and a host upgraded from 20.04 that kept the old conffile keeps it. That the Ubuntu 22.04 (rsyslog 8.2112.0-2ubuntu2.5) and 24.04 (8.2312.0-3ubuntu9.4) packages ship one shared stanza comes from the review's package extraction, not from this run; the run itself saw 24.04 (rsyslog 8.2312.0-3ubuntu9.2) only, and no 22.04 VM.
- Only logrotate 3.21.0 and 3.18.0 ran on VMs (the Go tests ran logrotate 3.22.0 locally); only mawk (Ubuntu) and gawk (AlmaLinux) were the helper's awk on the nodes. RHEL proper, `include`d policies, `su` directives and other quoting variants are covered by the Go harness with real `logrotate`, not by a VM.
- A failure after Step 1d, in Step 5c or later, can still leave the managed `/etc/logrotate.d/syslog` next to an unmodified distro policy (E1 BASE shows the mechanism); the playbook's rescue does not restore logrotate policies. Step 1d reads the policy again in Step 5b, so a change between the two is not covered.
- The spec's C20 row is a textual duplicate scan; it passes when a glob and a literal path collide (E2 BASE). The candidate prevents that case at apply time; the row was not changed.
- The nodes were fresh images plus fixtures; no long-lived host, no production inventory, no vault.

# `pilot_diagnose_dns_architecture`: every failed or unknown fact named, privileged principals refused — candidate `8951d2e` (2026-10-14)

This record follows `2026-10-14-e862f1d.md`; PR #66 merged as `1dad672`. A second review of #66's head `68c8f83` found these problems, all still on `main`:

- **[P2] Status `complete` while every FreeIPA fact was `auth_required`.** `kinit` exited 0 and then every `ipa` command said `did not receive Kerberos credentials`.
- **[P2] Failed lookups produced no finding.**
  - A provider's NS or SRV query that got SERVFAIL was still `observed`, and an NXDOMAIN was `absent`.
  - A client `getent` with rc 2 was `absent`.
  - In both cases the status stayed `complete`.
- **[P3] Principals.**
  - `-c/tmp@REALM` passed validation and was read by `kinit` as an option.
  - Service principals such as `host/` or `DNS/` were accepted.
  - The `--rights` output was never checked for write rights.
- **[P3] Wrong state from probes.**
  - The client's first hop used `+short`, so a REFUSED answer was read as "not a pilot dns tier host".
  - Any `systemctl` output other than `active` meant "not running", bus errors included.
- **[P3] Comparisons silently dropped.** An upper-case FQDN dropped the core comparison. Providers or tier hosts beyond the bound were skipped without a finding, `options` ignored its rc, and `@` was accepted as a name.
- **[P3] Test comment.** The comment on the playbook consistency test described its hang wrongly.

## Changes

`4dda916`, `5f98385` (staticcheck QF1002), and `8951d2e`, which merges `main` at `f9fb701`:

- **Status and findings.**
  - A FreeIPA fact that is `auth_required` makes the status `auth_required`, with a finding.
  - An error rcode is state `error` everywhere. NXDOMAIN, or no record of the asked type, is `absent`.
  - Every failed provider, tier or client query is named in `dns_query_failed`.
  - `named` stopped while SSH works is `freeipa_named_not_running`.
  - Unknown configuration facts, unknown comparisons, templated inventory values and skipped probes are named (`live_fact_unknown`, `comparison_unknown`, `declared_value_unevaluated`, `probe_skipped`).
- **Principals.**
  - No component may start with `-`, and `kinit` gets `--` before the principal.
  - FreeIPA's service principals (`host`, `HTTP`, `ldap`, `DNS`, `ipa-dnskeysyncd`, `krbtgt`, …) and `administrator` are refused at startup.
  - A principal whose `--rights` show write on the DNS configuration is `refused_privileged`, and nothing it read is used.
- **First hop.** The client's first hop reads the full `id.server` answer: REFUSED is a failed query, and NOTIMP is not a tier.
- **`systemctl is-active`.** Only rc 0 means running, and only `inactive`/`failed` with rc 3 means stopped. Anything else is unknown. `resolvectl` is `not_applicable` only when systemd-resolved is really stopped.
- **Names.** The primary's FQDN is lower-cased and stripped of its trailing dot before it is validated. An invalid one is `probe_skipped`, `@` is refused, and probes beyond the bound are `probe_skipped`. Every provider's internal answer is compared with the first one's.
- **Test.** The consistency test's comment now describes the captured failure: ansible-core 2.19.2's results thread raising `KeyError`, after which the run waits forever. Such a run is killed when the traceback appears and retried once.

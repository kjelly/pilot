## Real captures behind the parsers

Recorded under `internal/diagnose/testdata/dnsarch/` from the same topology by running each step's exact JSON args through `ansible <host> -m command -a …` (AGENTS.md §5.6). Facts they established:

| Fact | Effect |
|---|---|
| Without the three read permissions, `ipa dnsconfig-show` prints "Global DNS configuration is empty" and `ipa dns*-find` prints "Number of entries returned 0" with rc 1 — the same as nothing configured; `--rights` shows `'idnsforwarders': ''` | `permission_denied` from rights and from the server/zone entries FreeIPA must have, never a false `absent` |
| An empty `ipa dnsforwardzone-find` exits 1 | rc 1 with "Number of entries returned 0" is an empty result, not an error |
| `System: Read DNS Entries` targets `idnsname=*,cn=dns,…`, covering zones and forward zones | hidden zones imply hidden forward zones |
| `ipa dnsserver-find` shows the server's own forwarders and policy (`8.8.8.8`, `only`) next to the global list | separate per-server comparison |
| `unbound-control list_stubs` always includes `. IN stub prime <root servers>` | the root-hints stub is not an undeclared zone |
| dig to an unreachable server: rc 9, `;; communications error to 192.0.2.1#53: timed out` / `;; no servers could be reached`; to a stopped unbound: `connection refused` | error, never "no records" |
| a bad keytab path makes `kinit -k` fail with `Pre-authentication failed: Invalid argument` | `auth_required` with that text |
| ansible-core 2.19.2 maps `freeipa-server-replica-apply.yml`'s forwarder argv over a string `8.8.8.8` into seven `--forwarder=` flags | finding `freeipa_forwarders_invalid` |

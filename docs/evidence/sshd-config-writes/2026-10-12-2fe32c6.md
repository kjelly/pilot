# sshd -t before FreeIPA installers and their package installs (freeipa-server, freeipa-server-replica, freeipa-realm-replacement, freeipa-client) — candidate `2fe32c6` (2026-10-12)

Follows `2026-10-12-aca4915.md` (PR #50), whose `TestRegression_IpaInstallersRunAfterAnSshdCheck` allowlisted five installer runs:
- `ipa-server-install` (freeipa-server);
- `ipa-client-install` and `ipa-replica-install` (freeipa-server-replica);
- the realm replacement's `ipa-client-install --uninstall` and enrollment.

Each restarts sshd, or was assumed to. With a broken file in `sshd_config.d` the restart fails and sshd stays down.

What the runs below found:
- **The `dnf install` of the FreeIPA packages restarts sshd itself** on a fresh AlmaLinux 9 host (systemd "Queuing reload/restart jobs for marked units"). This happens before the installer. On `21bd0d7`, a check placed next to the installer refused correctly, but sshd was already down. The same gap applies to PR #50's check next to freeipa-client's enrollment, which `aca4915` only tested on a host whose packages were already installed.
- **`ipa-replica-install` did not restart sshd** while promoting an enrolled client.

The change:
- **freeipa-server, freeipa-server-replica (step 1) and freeipa-client** check `sshd -t` in pre_tasks, before any change and any package install. The check runs only while the installer is still to run (the installer's own `creates:`), is tagged `always`, and is read-only, so `--check` shows a refusal too. If it fails, the run refuses with sshd's message, and nothing was changed.
- **freeipa-realm-replacement** checks in pre_tasks, before the archive and the switch.
- **freeipa-server-replica step 2** has no check of its own: it guarded nothing.
- **Lint.** `TestRegression_IpaInstallersRunAfterAnSshdCheck` now:
  - counts a check anywhere earlier in the play;
  - fails a play that runs an installer and installs packages before its first `sshd -t`;
  - has an empty allowlist.

## Found while running, not changed

`freeipa-realm-replacement-apply.yml` writes its regexes in single-quoted YAML with doubled backslashes. Single quotes keep both backslashes, so the regex sees a literal backslash:
- "pin SSSD to the new server" has `insertafter: '^\\[domain/'`. The `[` that follows starts a character set that is never closed, so the task fails every time with "unterminated character set at position 3".
- Its `regexp: '^ipa_server\\s*='`, and "pin new server FQDN"'s `regexp: '\\s… (\\s|$)'`, never match and keep inserting lines.

`TestRegression_JinjaTemplatesUseSingleBackslashes` checks only `{{ }}` templates, so it misses these. They need their own fix and a full realm replacement run.

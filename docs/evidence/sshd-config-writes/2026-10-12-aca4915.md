# sshd configuration writes validated and put back on failure (freeipa-client, its decommission, pilot-access-target-policy) — candidate `aca4915` (2026-10-12)

Scope: the three writes that `TestRegression_SshdConfigWritesAreValidatedAndReverted` (PR #38) allowlisted, plus a fourth hazard of the same kind found while testing them:
- `freeipa-client-apply.yml` wrote `05-freeipa-client-password-auth.conf` with no check and **restarted** sshd.
- `freeipa-client-decommission.yml` removed that drop-in and restarted sshd, again with no check.
- `pilot-access-target-policy-apply.yml`'s absent path removed its drop-in outside a rescue. It reloaded only when the removal changed something.
- The fourth (found while testing): `ipa-client-install` and `ipa-client-install --uninstall` restart sshd themselves.

With another file in `sshd_config.d` broken, each of these left sshd down or out of step with its files.

The change:
- **The three writes.** Each now snapshots the drop-in, then writes it (`validate: /usr/sbin/sshd -t -f %s`) or removes it, runs `sshd -t` on the whole configuration, and reloads. All of this runs in a block whose rescue puts the drop-in back and fails the run.
  - freeipa-client and its decommission now reload instead of restarting.
  - target-policy removes its pre-change snapshot only after the reload.
- **The installers.** freeipa-client checks `sshd -t` before `ipa-client-install`, under the enrollment's own `creates:`. The decommission checks it before `--uninstall`. If the check fails, the run refuses with sshd's message and changes nothing.
- **Lints.**
  - `sshdConfigWriteAllowlist` is now empty.
  - The new `TestRegression_IpaInstallersRunAfterAnSshdCheck` requires an `sshd -t` before every `ipa-client-install`, `ipa-server-install` and `ipa-replica-install` run in `playbooks/apply` and `playbooks/decommission`. It allowlists five runs: freeipa-server, freeipa-server-replica ×2 and freeipa-realm-replacement ×2.

## Regression tests

`internal/spec/sshd_config_write_behavior_test.go` (new) runs each site's own tasks on localhost. It uses the ForceCommand tests' runner, now split out as `runLocalTasks`:
- sshd is a stand-in that fails on demand;
- the copy's `validate` is a stand-in;
- the reload is a debug task;
- the installers become `touch`, keeping their `creates:`.

The tests:
- `TestRegression_SshdConfigWritesPutBackOnFailure`, 10 cases:
  - the write sites: write, validate and reload; `sshd -t` failing with no drop-in before and with a previous drop-in; a drop-in that fails its own validation;
  - the removal sites: remove and reload; `sshd -t` failing after the removal, including that target-policy keeps its pre-change snapshot.
- `TestRegression_SshdConfigWritesRetryAfterAFailure`, 3 cases: after a failed `sshd -t`, the next run validates and reloads.
- `TestRegression_IpaInstallersCheckSshdFirst`, 6 cases, for the enrollment and the uninstall:
  - `sshd -t` passes: the installer runs;
  - `sshd -t` fails: the run refuses with sshd's message and the installer does not run;
  - a host the installer would skip is not blocked.

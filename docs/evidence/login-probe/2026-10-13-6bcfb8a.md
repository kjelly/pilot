## 4. Pre-existing defects found during this run (not changed here)

- **`prometheus-apply.yml` never restarts Prometheus for a `prometheus.yml`
  change when `alertmanager_target_host` is set.** The "Consolidate
  prometheus.yml result" task combines the changed render with the skipped
  alternative render; a skipped task's registered result still carries
  `changed: false`, so `default()` does not apply and `combine` overwrites
  `changed: true`. Re-applying Prometheus from the workspace inventory
  rewrote `prometheus.yml` (FQDN `pilot_host` labels, `changed=1`) but the
  container task reported `ok` and the running Prometheus kept the old
  labels. The lines date from `1ed49a3` (2026-07-07); the pattern occurs
  nowhere else in `playbooks/`. Prometheus was not restarted by hand
  (AGENTS.md §5.9).
- **`pilot host decommission` does not reconcile Prometheus scrape targets**
  (host-decommission spec §19's first active-residue example has no
  implementation): after the decommission the retired host was still being
  scraped and `HostDown{lp-target}` went pending.

# Login probe alert routing, decommission and probe fixes — candidate `dc883b3` (2026-10-15)

This record follows [`2026-10-15-0882d2c.md`](2026-10-15-0882d2c.md). That record's HostIOStall firing still stands, because the HostIOStall expression has not changed since. A review of PR #80 at `a742ad9` found three P2s and several P3s. `dc883b3` fixes them:

| Finding | Fix |
|---|---|
| P2-1a: on a data gap, `HostDown` (10m, critical) inhibited `HostMetricsMissing` (3m). The operator saw only "Target down", and Teams mode sent nothing saying the host was up. | `HostMetricsMissing` now inhibits `HostDown{job="node"}` of the same `pilot_host`. It carries `action_required="true"`, so Teams mode delivers it. `prometheus-apply.yml` refuses a `host_metrics_missing_for` of 10m or more. |
| P2-1b: a dead host raised `PilotLoginProbeTransportFailed` (5m) before `HostDown` (10m). | The rule excludes hosts with `up{job="node"} == 0`, so a dead host yields only `HostDown`. No rule uses `HostDown` as an inhibit source any more, so `HostDown{job="dcgm"}` mutes nothing (P3-5). |
| P2-2: `PilotLoginProbeStale` inhibited with `equal: ['site']`, so one stalled probe muted every probe in the site. | Every login-probe alert keeps the probe host as `probe_host`, and the inhibit matches on it. `Stale` carries `action_required="true"`. |
| P3: a frozen `success=1` turned a dead host into "SSH reachable, metrics missing". | `HostMetricsMissing` only trusts a probe whose textfile is younger than `login_probe_stale_seconds`. |
| P2-3: the decommission re-render of login-probe hosts passed no vault. | The re-render passes the workspace's `.vault/main.yaml` as `-e @<path>`, as `pilot deploy` does. |
| P3-1: a SIGTERM mid-login was recorded as a PAM account denial. | A canceled attempt has no result: it is not recorded, and a partial round is not written. |
| P3-2: the direct-connection branch of `authenticatedRe` was wrong. | Fixed against a real OpenSSH 9.6p1 direct login, captured as `testdata/capture/ok-direct-ubuntu`. |
| P3-3: CI skipped the promtool test. | CI's Playbook lint job runs `make alert-rules-test`. That target pulls the pinned images, and `PILOT_REQUIRE_CONTAINER_TESTS=1` turns a skip into a failure. |
| P3-5: one unresolvable target blocked the whole deploy and the re-render. | The unresolvable target stays a target with a warning. Only "no target resolves" is refused. Explicit target names and role removal are documented. |
| Found in this run: `--check --diff` of an already-deployed probe host failed in the rollback snapshot. | Check mode takes no snapshot and restores none. |

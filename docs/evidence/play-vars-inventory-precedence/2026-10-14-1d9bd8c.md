# SIEM port numbers, log root by its real path, logrotate — candidate `1d9bd8c` (2026-10-14)

> Superseded for PR #79 by [`2026-10-16-56c7582.md`](2026-10-16-56c7582.md). This run used an earlier candidate and does not record the target image digest, run IDs or input fingerprints; the gates it checked are covered by Ansible-run regression tests, and it is not evidence for the current candidate.

This record follows `2026-10-14-78cf68c.md`. A third review of PR #79 at `9726128` found no P1 or P2. It found six P3 problems:

- **Ports.** Preflight and the playbooks accepted port values that rsyslog, Wazuh or Promtail read differently, or not at all: `2514.0`, `1e3`, `0x9C4`, `02514`, `70000`, `-1` and `true`. A `0` silently became the default.
- **The `siem_log_root` gate was too strict.** It refused:
  - a symlink anywhere on the path, so a host whose `/var` or `/var/log` is a symlink failed even with the default path;
  - the root of a newly mounted filesystem;
  - and, without a remedy in its message, a directory whose mode had changed.
- **The port-match gate recognised the log-server only by inventory name or `ansible_host`.** A different case, a trailing dot or its FQDN went unchecked.
- **logrotate.**
  - The `validate` failed on a host without logrotate, and neither playbook installed it. `pilot-target-ubuntu` does not ship it.
  - It passed an error that has no line number: a postrotate block without `endscript`.
- **C22** waited 3 s and did not check where the connection went.
- **The log-root regression test** skipped entirely, name checks included, when the user's primary group name differs from the username.

## logrotate `validate`

The rule is `logrotateSyntaxCheck`. It fails when `logrotate -d` prints an error naming the policy file (`error: <file>:`), with or without a line number.

| Policy | logrotate 3.21.0 (workstation) | logrotate 3.18.0 (`pr79-el`) |
|---|---|---|
| valid, with postrotate/endscript | pass | pass |
| `rotate ` (empty) | fail: `error: <file>:3 argument expected after rotate count` | fail, same message |
| `rotate abc` | fail | fail: `error: <file>:3 bad rotation count 'abc'` |
| unknown option | fail: `error: <file>:3 unknown option 'bogusoption' -- ignoring line` | fail, same message |
| postrotate without endscript | fail: `error: <file>:prerotate, postrotate or preremove without endscript` | fail, same message |

The previous rule (`grep -E "^error: [^ ]+:[0-9]+ "`) passed the last row. logrotate's other errors (`error opening state file`, `error: skipping ...`) do not name the policy file.

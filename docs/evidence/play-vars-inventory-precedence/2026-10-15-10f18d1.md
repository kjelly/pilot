# SIEM probes on the effective log root, confined rsyslogd — candidate `10f18d1` (2026-10-15)

This record replaces `2026-10-15-fa00d18.md` as the current record for PR #79. That record has the background:

- **[P2]** `log-server.md` C6–C8 checked `/var/log/siem` even when `siem_log_root` set another root. An old fixed selftest string could make C7/C8 pass.
- **[P3]** The committed VM summaries lacked the fields required by `docs/actual-run-evidence.md` §3.
- **The VM run of `8820b04`** found that rsyslogd cannot write a root outside `/var/log`:
  - Ubuntu 24.04 confines it with AppArmor.
  - EL confines it with SELinux, which allows `var_log_t` only.
  - In both cases every message was discarded while the apply succeeded.

A review of `fa00d18` found three problems in its new log-root access step. The first two were reproduced on `pr79-el` (AlmaLinux 9.8, SELinux Enforcing) of the `fa00d18` topology:

1. **`--tags C7` with a root not created yet failed.**
   - Step 2 created `siem_log_root` only under C6. Step 2a, which runs `restorecon` on that directory, also runs under C7 and C8.
   - With `-e siem_log_root=/srv/siem-el2 --tags C7`, the run failed at `restorecon: lstat(/srv/siem-el2) failed: No such file or directory`, rc=2.
   - The rescue then removed the drop-ins of the receiver that was running.
2. **The rerun after that failure left the root unlabelled.** The rerun used `fa00d18` with only the Step 2 fix below.
   - `restorecon` ran only when the file-context rule changed in that run. The rule had already been added by the failed run.
   - The directory Step 2 then created stayed `unconfined_u:object_r:var_t:s0`.
   - The apply succeeded, and a message sent from `pr79-client` was not written: no file under `/srv/siem-el2`, and a `Permission denied` in the rsyslog journal.
3. **The resolved root went into the AppArmor rule unchecked.** A symlink to a path with a space would break the rsyslogd profile, and a glob character (`*`, `{a,b}`) would grant other paths.

`10f18d1` fixes all three:

1. Step 2 now runs under C6, C7 and C8.
2. The relabel follows the directory's label (`stat -c %C`), not the rule's change flag. A check after the relabel fails when the type is still not `var_log_t`. Step 6a restarts rsyslog when the relabel ran.
3. The resolved-path gate takes only the characters that `siem_log_root` itself may use.

## Regression tests

**`TestRegression_LogServerRescueRestartsOnlyAValidConfiguration`** runs the restart condition and the message through Ansible. The accepted and rejected cases use the full `stderr_lines` of `rsyslogd -N1 -f /etc/rsyslog.conf`, as `register` recorded them on `pr79-dev`, an Ubuntu 24.04 VM with rsyslog 8.2312.0 (2026-10-16 01:06 UTC; the VM was torn down afterwards):

- accepted: rc=0, 2 lines (`version 8.2312.0, config validation run …`, `End of config validation run. Bye.`);
- rejected (`/etc/rsyslog.d/99-pr79-broken.conf` holding `this is not rsyslog syntax {`): rc=1, 8 lines. They are the version line, five `error during parsing … warnings occurred` lines, `error during parsing … syntax error on token '{'`, and `could not interpret master config file '/etc/rsyslog.conf'`.

Its results:

- With `d545868`'s playbook, the rejected case fails: the message quoted only the last line.
- With the condition reversed to `!= 0`, all four cases fail (see `2026-10-15-d545868.md`).

**`TestRegression_SIEMPortsAreTCPPortNumbers`.** The counts are corrected from the `d545868` record:

- At `7db53f2` it made 27 `ansible-playbook` runs per gate (8 accepted values, 18 refused values, unset), 108 in all. It now makes 1 per gate, 4 in all.
- Loosening the `loki_port` gate's regex makes it fail; the values below were read from `go test -json` output, nothing truncated:
  - `^[0-9.]+\Z` (end anchor kept): it fails for 6 values: `0`, `"0"`, `2514.0`, `"2514.0"`, `1e3`, `"02514"`.
  - `^[0-9.]+` (end anchor dropped): it fails for 9 values, the 6 above plus `"0x9C4"`, `"2514 "` and `"2514\n"`.

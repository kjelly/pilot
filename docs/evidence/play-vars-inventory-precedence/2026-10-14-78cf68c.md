# SIEM inputs: preflight types, gates, SELinux ports — candidate `78cf68c` (2026-10-14)

This record follows `2026-10-14-ae31940.md`. A review of PR #79 at `31f97a6` found these problems:

- **Preflight rejected valid inventories.** `ansible-inventory --list` JSON turns numbers into float64, while preflight accepted only an int for `integer` and only a string for the ports.
- **The `siem_log_root` gate checked names only.** A symlink, or another service's directory, passed.
- **The sender and receiver ports were never compared.**
- **An empty logrotate count rendered `rotate `.**
- **The §1.5 lint over-claimed.**

The VM runs then found two more problems:

- **Plain `logrotate -d` rejects Ubuntu's distro rsyslog policy.** Run on that policy alone, it reports an error.
- **SELinux blocks non-default ports on EL.** rsyslogd may not use them, so forwarding silently stops.

## SELinux on the AlmaLinux client

**Before, on `e20cdab`:**
- With `siem_forward_port: 2514`, `pr79-el`'s rsyslogd logged `cannot connect to siem-log-server:2514 (took 0.00 seconds): Permission denied` and suspended the omfwd action. Every forwarded message was lost while the apply succeeded and C16/C17 passed.
- No AVC was logged (dontaudit).
- After `systemctl restart rsyslog`, the C22 command (via `pilot verify --probe`) returned 1 (FAIL).
- `seobject` listed no record of its own for tcp/2514 (it is only in the `unreserved_port_t` range 1024–32767), and `rsh_port_t` for tcp/514.
- `sesearch -A -s syslogd_t -c tcp_socket` (setools-console, installed for this capture only): syslogd_t has `name_bind name_connect` on `rsh_port_t` and `syslogd_port_t`, and none on `unreserved_port_t`.

**After, on `ea62947` and later:**
- The task file labelled tcp/2514 `syslogd_port_t` and restarted rsyslog.
- rsyslogd then held an ESTABLISHED connection to `:2514`, the message arrived on `pr79-log`, and C22 passed.
- Two more checks:
  - Deleting the label and re-applying: the label task changed, Step 9a restarted rsyslog, and the next message arrived.
  - `log-server-apply.yml` with `siem_receiver_tcp_port: 2514` on `pr79-el` (as the receiver, after deleting the label): the label task changed and Step 6a restarted rsyslog (rc=0, ok=21 changed=5). Delivery to that EL receiver was not checked; the run was stopped there.

**Other configurable ports on EL do not need labels.** A service started by systemd from `/usr/local/bin` (as node_exporter, restic and pilot-session-store are) runs as `unconfined_service_t` on `pr79-el`. wazuh-manager's containerized `syslog_output` is not verified (#86).

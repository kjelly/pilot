`032a8b3` changes the message to quote the last `error during parsing` line that is not rsyslogd's `warnings/errors occurred in file …` summary. Without such a line, the message quotes the last line, then Ansible's message.

What the message quotes depends on what `rsyslogd -N1` (rsyslog 8.2312.0) reports:

- **Invalid syntax**: the line with the error and the drop-in's name.
- **`action(type="omfile")` without a file**: the line with the omfile error. `939b3fe` quoted the `errors occurred in file` summary that follows it.
- **An unterminated block in a drop-in**: the error, which rsyslogd blames on `/etc/rsyslog.conf, on or before line 54`, not on the drop-in.
- **An unknown directive, or a module that does not load**: rsyslogd prints no `error during parsing` line, so the message quotes its last line, which states the problem.

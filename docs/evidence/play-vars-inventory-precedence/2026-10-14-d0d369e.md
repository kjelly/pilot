# Play vars no longer shadow inventory inputs — candidate `d0d369e` (2026-10-14)

Follows `2026-10-13-dff8d79.md`. A review of `dff8d79` found that the change broke one inventory input it made effective:

- **log-shipping and log-server disagreed on `siem_log_root`.** log-shipping reads `siem_log_root` from inventory since `dff8d79`. log-server, which writes the files Promtail tails on the same hosts, still declared it in its play vars. `docs/verification/log-shipping.md` §1.5 requires both to use one value. With `siem_log_root` set in `group_vars`, rsyslog kept writing under `/var/log/siem` while Promtail tailed the operator's directory.
- **`siem_forward_port`** is an input of wazuh-manager (its `group_vars` example). audit-log-forwarding still declared it in its play vars.

`d0d369e` defaults both in an always-tagged `set_fact`, as the other moved inputs. The lint now checks every apply playbook against the inventory inputs of every contract, not only its own. It also merges `main` (`dcdef4b`).

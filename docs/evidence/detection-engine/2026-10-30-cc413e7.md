Each fault case independently checks the executable SHA256, SQLite
PRAGMA integrity_check and marker value, service active/enabled state,
original configuration/provider contents and file modes. Shared stale backup
sentinels are checked to remain unchanged. Failure is caught only at the
production rescue's final failure task; each scenario then independently
checks the resulting binary, data, configuration and service state. No service modules, owner/group or become
settings are stripped from production tasks in the VM driver.

The existing file-level Ansible regression suite also passed in the same
workflow. It covers tag selections, service-state query refusal, original
unit/config/profile/provider restoration, symlinks, metadata, secret-safe
logging and read-only check mode. Its mock systemctl/SQLite behavior is not
used as the evidence for the VM results above.

## Process lesson: don't delegate a long-running wizard apply to a time-boxed subagent

Two consecutive subagent attempts at the site-wide deploy checkpoint were lost to session/process
lifetime limits before producing any real mutation (see Provenance above). From that point on, every
checkpoint containing a multi-minute-to-tens-of-minutes real `pilot deploy`/`pilot reconcile` apply
was run directly by the controller's own background shell, which completed every one of them without
further interruption. Bounded, single-turn exploration and script-authoring work remained well
suited to delegation throughout (used for the workspace build and roster authoring checkpoints).

## Findings reported, not fixed (out of this round's authorized scope)

- **`host-monitoring` role is absent from both this runbook's §0.5 role table and
  `docs/topologies/minimal-poc-topology.yaml`**, despite being a real, current role in
  `internal/inventory/contracts.go`/`cmd/pilot/cmd/deploy_catalog.go` (with its own
  `node_exporter_basic_auth_password` vault requirement, already listed in this runbook's §2). With
  the group empty, Prometheus has zero real node_exporter scrape targets in this topology, and §4.2's
  own `up` check is satisfied entirely by Prometheus's own `job_name: prometheus` self-scrape — a
  plain `up` query cannot distinguish "the monitoring pipeline actually covers hosts" from "zero real
  targets exist." This is a scope-completeness gap, not a defect in the current documented
  procedure (which is internally consistent and was followed and verified exactly as written) —
  adding the role is a scope decision for the user, not something this evidence-gathering round
  should decide unilaterally. The same gap was independently found and partly addressed (for a
  different scenario, `.agents/skills/delivery-test/SKILL.md`) earlier the same session.
- **`freeipa-identity-apply.yml`'s own top-of-file comment claims the roster's top-level
  `nfs_clients` field is "reconciled only by `freeipa-nfs-client-apply.yml`"**, but that playbook
  never loads the roster at all — the comment appears stale or the field may be dead. Informational
  only; no behavior depends on it in this round's scope, and fixing a code comment was not
  authorized.

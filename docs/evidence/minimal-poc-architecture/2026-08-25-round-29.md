| 2 | Fatal on all three hosts, same task: `wazuh-fim-apply.yml`'s "Pin wazuh-manager -> ... in /etc/hosts" wrote `{{ wazuh_manager_host }}` (an FQDN) verbatim into the IP column | **Real bug.** `/etc/hosts` requires a literal IP in column 1; glibc/systemd-resolved silently ignore a non-IP first column. The task still reported `changed: true`. First fix attempt (a plain `socket.gethostbyname()` resolution) itself broke on the re-run: it ran on `client-vm` before that host's own resolver was pointed at FreeIPA DNS (that only happens in the later, separate `freeipa-dns-client` single-component deploy, §3.7), so the live DNS lookup failed outright. |

Only `wazuh-fim`'s and `restic-backup`'s had actually failed live so far; the other 6 hadn't been reached yet in `site.yml`'s play order. Stopped and authorized live (scope: fix all 8) before fixing; extracted a shared `tasks/resolve-hosts-alias-target.yml` (resolves via this inventory's own `hostvars` first, live DNS only as a fallback for genuinely out-of-inventory targets) and wired it into all 8 call sites (commit `338bf83`). |
| **4** | **`✅ 套用完成`, `failed=0` on all hosts** | Clean pass. See below. |

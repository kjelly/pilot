## Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| G1 | low | The Ansible fact-cache entries of the five inventory names survived `pilot vm-target topology down` and `topology up`. `internal/factcache` resolves the cache directory with `ansible-config` from the working directory's `ansible.cfg` (`~/.ansible/pilot-factcache`), while `pilot deploy`/`pilot reconcile` set their own cache to `<data-dir>/ansible/fact-cache` (`prepareDeployAnsibleRuntime`), so the teardown cleans a different directory than the one deploy reads. A VM rebuilt under a name used within the last hour is served the old VM's facts. This corrects the F6 assessment of round 32 ("already dropped by `vm-target up` and teardown"), which was true only for the `ansible.cfg` directory | **open, no product change made; filed as kjelly/pilot#336** (stop condition; proposed direction: `factcache.Drop` also cleans the deploy runtime's directory, or deploy reuses the `ansible.cfg` cache). Mitigation used in this run: the five entries were removed by hand before the first deploy (runbook §3.10) |

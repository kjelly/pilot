## Documentation defects found — six, four of them in the runbook

No product defect was found this round. Every finding below is a documentation defect,
and all six are corrected in the runbook or recorded here.

1. **§6.1's isolated-cwd workaround was actively broken (high).** It said to symlink
   every repo-root entry "except `group_vars`/`host_vars`/`.vault`/`tmp`". That single
   directory holds both the stray shadowing `*.yml` and the repo's 13 legitimate
   `*.example.yml` templates that `pilot inventory generate` copies from. Following the
   instruction produced a workspace with **zero group_vars files, and `inventory
   generate` still exited 0** — a silent omission, not an error. Corrected: symlink a
   `group_vars/` containing only the examples plus the `dns/` example dir.
2. **§3.3 claimed the two authoring routes produce identical files (high).** They do
   not. `autofillCrossRoleHostVars` is reachable from exactly two places — the quick
   path calls it explicitly, and `pilot edit`'s group_vars picker calls it *only in the
   create-from-example branch*. `copyMissingGroupVars`, which `pilot inventory generate`
   uses, copies verbatim with no autofill, and a later `pilot edit` pass cannot recover
   it because the file now exists. The documented order therefore leaves **seven**
   derivable values empty. Corrected in §3.3.
3. **`pilot deploy` asks one `[Y/n]` per auto-detected `-e`, undocumented (high).** This
   inventory produced **seven** (`siem_forward_host`, `wazuh_manager_host`,
   `restic_s3_target_host`, `thanos_s3_target_host`, `thanos_query_target_host`,
   `loki_target_host`, `alertmanager_target_host`), all resolving to `nexus`. The count
   is data-dependent on which roles the inventory places. Answering the wrong number
   sends the next keystroke into the following prompt: this round's first attempt
   answered `n` — meant for the sudo question — into the `siem_forward_host` confirm,
   **declining a derived value**, which the wizard input policy forbids. It failed
   safely only because a later `EXPECT` timed out. Documented in §3.4 with the full
   prompt sequence.
4. **Checking `freeipa-nfs-server` fires three chained auto-prompts on one confirm
   (high).** In order: the masked admin-password prompt from the NFS roster bootstrap;
   then, when the host also has `prometheus`, an inline `prometheus_site_label` prompt;
   then the `host_vars/<host>.yml` key-list editor, which must be saved explicitly.
   Saving the third returns to that **host's own menu**, not the roles menu, so this
   host never shows the `✅ 完成` row the others do. Cost three scripted attempts.
   Documented in §3.3.
5. **A derailed wizard run is not always side-effect-free (medium).** The ordinary
   editors only write on explicit save, but the auto-bootstrap paths write immediately —
   an attempt that died before any save had already created `.vault/ipa-identity.yaml`,
   `.vault/main.yaml` and `host_vars/<host>.yml`. Scripted attempts need the workspace
   wiped between runs to stay deterministic. Documented in §3.3.
6. **`TEXT_IF`'s guard matches scrollback (medium, trec-driver).** Neither wizard uses
   an alternate screen buffer, so a guarded answer loop sized one larger than the real
   prompt count re-matched the previous prompt and typed a stray character into the
   following **text field** — the manual `-e` field the policy requires be left empty.
   Clear that field (Ctrl-U) before submitting it empty. Durable home is the trec skill
   per AGENTS.md v1.15; recorded here as the reproduction.

## Two suspected product gaps — reported, not fixed

Per the skill's stop condition, no playbook, role, task, or Go source was modified.

- **The NFS bootstrap's minimal vault permanently blocks skeleton completion.** The
  bootstrap creates `.vault/main.yaml` with exactly one key during hosts.yml authoring.
  `pilot inventory generate`'s never-overwrite policy then reports "already exists, left
  untouched" and never adds the rest — measured **1 of 8 required keys**. The remaining
  seven must be filled by hand, with no tool-generated list of what they are. Two
  workarounds exist: render a throwaway skeleton with `--vault-out <scratch>
  --no-group-vars --no-host-vars --no-nfs-roster` and diff it, or delete the
  bootstrap-created vault and re-run `inventory generate` (only safe when you know the
  one value it held). A proper fix would let `inventory generate` add missing keys to an
  existing vault.
- **A vault-fill wizard cast can never pass the recording gate.** The fill itself
  succeeded — all 8 keys set on disk, every declared secret properly redacted, and
  literal greps for all six secret values clean. Yet `trec verify` **failed**: "secret
  scan found 33 likely unredacted secret(s)", all `inline-secret-assignment`. They are
  not leaks. The vault key-list screen renders `<key> = <value>` for every key each time
  it opens, and the scanner's rule fires on that *pattern* — matching the shipped
  `CHANGE-ME-…` placeholders and even redacted or empty values. The recording gate and
  the vault editor are structurally in tension: the cast was demoted to a diagnostic and
  the checkpoint's state claim rests on the on-disk key check instead.

## Scope

A design discussion (this session) established that the `internal-endpoint` reconciler already has
everything needed to give any deployed web service a `<name>.it.pilot.internal` domain + a genuine
FreeIPA-issued HTTPS certificate — proven for Grafana in round 25 — but doing so requires hand-authoring
a manifest entry per endpoint. This round built and live-tested a **suggester**: a mechanism that
proposes ready-to-use manifest entries for contract endpoints explicitly opted in via a new
`autoPublish.eligible: true` field, resolved against this topology's real inventory group membership,
without ever writing a file or reconciling a live host itself (that discipline stays with the existing
`SimulateAddInternalEndpoint`/`AppendInternalEndpoint` gate every manual entry already goes through).

Explicitly out of scope, per the same 2026-08-14 decision recorded in this project's own memory: no
non-interactive `pilot reconcile internal-endpoint`-style CLI. The new `suggest` subcommand only ever
prints candidates; a human still drives every write, either via `pilot edit`'s new checklist menu item
or by hand-pasting the printed YAML.

## What was built

- `internal/contract/contract.go`: `Endpoint` gained `AutoPublish *AutoPublish{Eligible, Subdomain,
  Reason}`. New validation rule: `eligible: true` is rejected on any endpoint whose `scheme` isn't
  `http`/`https`.
- Contract annotations, every one carrying an explicit `reason` whether eligible or not (no silent
  exclusions):
  - `dashboard.yaml`: `grafana` → eligible (`subdomain: grafana`); `loki` → ineligible (Grafana's own
    datasource wiring, not a human-facing page).
  - `wazuh-manager.yaml`: new `dashboard` endpoint (`https:8443`, matching round 25's port-443-conflict
    fix) → eligible, `subdomain: wazuh-dashboard` (see Finding #1 below for why not `wazuh`).
  - `freeipa-server.yaml`: `https`/`httpBootstrap` → ineligible. FreeIPA is the trust root
    `internal-endpoint` itself depends on (`sameHosts`, required); routing its own web UI through the
    same reverse-proxy mechanism would be circular, and its cert SAN/Kerberos SPN are bound to
    `freeipa_domain` at install time, not to a reverse-proxy-assigned name.
  - `prometheus.yaml`/`alertmanager.yaml`/`thanos-query.yaml` → ineligible. No auth of their own;
    publishing them through the shared reverse-proxy would put unauthenticated operational surfaces on
    the same trust boundary as user-facing apps.
  - `keycloak.yaml`: considered eligible during design, **corrected before implementation finished** —
    `keycloak-apply.yml`'s `KC_HOSTNAME` is hardcoded to `idp.infra.internal`, not derived from any
    internal-endpoint FQDN; fronting it under a different name would issue OIDC tokens whose `iss`
    claim doesn't match the URL clients used to reach it. Marked ineligible with that reason. This
    correction was found reading the playbook during implementation, not during a live test — keycloak
    is not deployed in this topology (`inventory.yml`'s `keycloak` group is empty) so it was never
    exercised live.
- `internal/inventory/internal_endpoint_suggest.go`: `SuggestInternalEndpoints(contracts, groups,
  proxyHost, zone, existing)` — pure, no disk/host I/O. Skips (with a stated reason) any eligible
  endpoint whose component isn't present, whose inventory group has more than one host (ambiguous,
  never guessed), whose upstream host:port is already published, or whose subdomain collides with
  another candidate in the same run. 7 unit tests cover each branch.
- `pilot internal-endpoint suggest` (new CLI subcommand, `cmd/pilot/cmd/internal_endpoint_cli.go`):
  read-only, auto-resolves the publishing zone from a single-zone `freeipa-dns.yaml` and the proxy
  host from a single-host `reverse-proxy` inventory group, errors (never guesses) on ambiguity. 4 CLI
  tests, run against the real `ansible-inventory` binary (`requireRealAnsible` guard, already an
  established pattern in this codebase).
- `pilot edit`'s internal-endpoint menu (`cmd/pilot/cmd/edit_tui_internal_endpoints.go`): new
  "🔎 從已部署服務建議 endpoint" item — same auto-resolution as the CLI, presents candidates as a
  checklist, and routes every accepted selection through the exact same
  `SimulateAddInternalEndpoint → AppendInternalEndpoint` chain a manually authored entry already uses.
- Side-effect fix: adding `wazuh-manager`'s `dashboard` endpoint widened `wazuh-fim`'s
  `providerEndpoint` dependency (no `endpoints:` filter) to include it in networkcheck planning, which
  `wazuh-fim` never actually needs. Narrowed with an explicit `endpoints: [agent, agentAuth]` filter,
  the same idiom `freeipa-client.yaml` already uses — caught by
  `TestPlan_WazuhFimToWazuhManager_IncludesAgentAuthPort` failing, not by inspection.

`go build ./...` clean; `go test ./...` — **1749 passed, 0 failed, 1 skipped, 22 packages** (final
count, after every fix in this round).

## Live test against round 25's running topology

### suggest, dry-run, against the real manifest

```
$ ./pilot internal-endpoint suggest \
    --inventory tmp/minimal-poc-20260814-round25/demo/inventory.yml \
    --freeipa-dns-manifest tmp/minimal-poc-20260814-round25/demo/freeipa-dns.yaml \
    --manifest tmp/minimal-poc-20260814-round25/demo/internal-endpoints.yaml

# wazuh.it.pilot.internal (wazuh-manager.dashboard) — paste this entry into internal-endpoints.yaml's endpoints:
- dns: {zone: it.pilot.internal.}
  fqdn: wazuh.it.pilot.internal
  route: {mode: reverse_proxy, proxy: {inventory_host: nexus, provider: nginx},
          upstream: {inventory_host: nexus, port: 8443, scheme: https, tls: {verify: false}}}
  state: present
  tls: {mode: freeipa}

# skipped:
#   dashboard/grafana: upstream nexus:3000 is already published by an existing endpoint
```

Zone (`it.pilot.internal.`) and proxy host (`nexus`) were both auto-resolved with no flags beyond
`--freeipa-dns-manifest` — the real `freeipa-dns.yaml` declares exactly one zone, the real
`inventory.yml`'s `reverse-proxy` group has exactly one host. `keycloak`/`prometheus`/`alertmanager`/
`thanos-query` correctly produced no output at all (ineligible, not even listed as "skipped" noise) —
confirmed the "silent for ineligible, explicit for eligible-but-blocked" design holds on real data.
Re-running without `--manifest` (fresh-slate scenario) correctly suggested both `grafana...` and
`wazuh...` together.

### Finding #1 — a genuine subdomain collision, caught before it ever reached a live host

Appending the suggested `wazuh.it.pilot.internal` entry and validating:

```
$ ./pilot internal-endpoint validate --manifest .../internal-endpoints.yaml --freeipa-dns-manifest .../freeipa-dns.yaml
[dns ownership conflict] endpoint "wazuh.it.pilot.internal": (it.pilot.internal., wazuh, A) is already explicitly managed by freeipa-dns.yaml
```

`freeipa-dns.yaml` already owns an explicit `wazuh` A record (created round 25 §3.6, for direct access
to the manager's own agent ports 1514/1515) — an unrelated, pre-existing use of the exact same short
name the dashboard's default `subdomain` would have claimed. **This is the DNS-ownership-collision gate
working exactly as designed**, not a bug in the suggester — it correctly refused to double-claim a name
rather than silently producing an ambiguous/wrong DNS record. Corrected the candidate to
`wazuh-dashboard.it.pilot.internal`; validate then passed cleanly. Since this collision is intrinsic to
this specific reference topology's existing naming convention (not a one-off authoring accident), the
contract's default `subdomain` was corrected from `wazuh` to `wazuh-dashboard` (see "What was built"
above) so a future run of `suggest` against this same reference topology doesn't reproduce it.

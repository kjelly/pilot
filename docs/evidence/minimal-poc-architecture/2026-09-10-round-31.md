## A self-caught driving mistake — C25's `freeipa-dns` idempotency check

The first attempt at the `freeipa-dns` idempotency rerun was silently a no-op: the assistant
answered the wizard's final "apply now?" confirmation by pressing ENTER on an *assumed* default
("Yes", based on every earlier Yes/No prompt in this round having "Yes" as the leftmost/highlighted
option), without checking which option was actually highlighted. `mcp__trec__terminal_read_screen`
renders both options as plain unstyled text with no highlight indicator, so the assumption was
never actually verified against that specific prompt — whose real default was "No". The wizard
correctly treated this as a clean decline and exited (`SESSION_END status=success exit_code=0`)
with no preflight/preview/apply output at all. Caught immediately by noticing the cast had zero
`PLAY RECAP`/`changed=` lines despite a "successful" exit code. Redone cleanly by reading raw ANSI
(`mcp__trec__terminal_read`, not `terminal_read_screen`) before every subsequent Yes/No
confirmation, using inverse-video styling to identify the true default and `LEFT`/`RIGHT` to move
the highlight when the desired answer differed from it. The retry produced genuine `changed=0`
evidence for both the `freeipa-server` dependency and `freeipa-dns` itself. This was a tooling/
driving-process mistake, not a `pilot` product defect — the wizard behaved exactly as asked at
every step.

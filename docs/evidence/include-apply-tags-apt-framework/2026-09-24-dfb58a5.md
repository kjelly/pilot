## Test-environment notes (not product changes)

- After each `topology rollback` the guest clocks were set from the controller with `date -u -s`. The revert restores the snapshot-time clock, and chrony only slews. An AlmaLinux guest was still 2247 s slow, so its `ipa-client-install` failed TLS: "SSL peer certificate or SSH remote key was not OK".
- One topology test attempt failed at `ipa-server-install`: the forwarder check to 8.8.8.8 timed out. 8.8.8.8 answered 5/5 right afterwards, and the rerun passed.
- One attempt of the full-verify topology test failed only freeipa-client C5/C8. Those rows need `freeipa-client-fixtures.yml` on the server first, which cannot run before the server exists inside a single topology test. The formal run verified freeipa-server inside the test and ran the fixtures and client verify afterwards.

## Not tested

- **dcgm-exporter** (`apache2-utils` via the apt framework): the playbook ends on hosts without an NVIDIA GPU, so no vm-target reaches that step. Running it on the real GPU host was declined for now; it stays unverified.
- **NFS automount** on `rbk-cl`: the mount-verification task (`ignore_errors: true` by design) reported the share not mounted, both before and after these commits. This matches the known client-side DNS registration gap for NFS.

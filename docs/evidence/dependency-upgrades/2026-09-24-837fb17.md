## Fleet-vars flow

Steps: top menu → `hosts.yml` → accept path → `共用變數` → add `ansible_user=ubuntu` → edit it to `admin` → add `scratch_var=temp` → `刪除` → Esc → `💾 存檔並離開` → `離開`.

| Run | Build | Driver | Result | Saved `hosts.yml` |
|---|---|---|---|---|
| 1 | candidate | strict: `ASSERT` right after the second add | `status=success`, exit 0, final `SESSION_END` success, integrity ok, secret scan clean | `vars: ansible_user: "admin"`, no `scratch_var` |
| 2 | baseline | same as run 1 | **failed** at `ASSERT 變數值` | not saved (run aborted) |
| 3 | candidate | v2: `EXPECT` instead of those two `ASSERT`s | success, same checks as run 1 | identical to run 4 |
| 4 | baseline | v2 | success, same checks as run 1 | identical to run 3 |

**Run 2 was a transient rendering glitch in the baseline, not in the candidate.**

- To change the label `變數名稱` to `變數值`, the baseline renderer moved the cursor 10 columns left and wrote only `值` plus erase-line. The PTY emulator rendered the line as `┃ 變數名稱值` for about 0.5 s, until the next full redraw.
- The candidate renderer rewrites the whole line, so it never shows that frame.
- The same full-line redraws are why the candidate's recording of the flow is about twice the size (≈45.7 KB vs ≈23.5 KB), and why the fleet-vars teatest needed its fix.

## sudo in the sims

In every hostauthz and audit sim run, the sim's own kinit as the test user (in its private cache) and its SSH login succeeded, and no cache was left afterwards. Only the `sudo -n` step varied:

| When | web (`pr72-ta`) | db (`pr72-tb`) |
|---|---|---|
| right after the first demo fixtures and user setup | `sudo: a password is required` | `sudo: a password is required` |
| 16 minutes later | pass | `sudo: a password is required` |
| right after a cleanup and rebuild of the same fixtures | — | pass |

audit sim: the first run failed the same way, and a rerun passed.

The sims assume a client sees a sudo rule as soon as the fixtures create it. SSSD only fetches new rules at its sudo smart refresh (default 15 minutes, per host), and only drops deleted ones at the full refresh (6 hours). So the result depends on the client's cache, not on the tested configuration. The last db pass most likely read a rule cached before the cleanup.

Per AGENTS.md §5.9 that is a fixture bug. It was not worked around here: no `sss_cache`, no restart. It is filed as #95. The sudo step does not use a Kerberos cache, so `main` behaves the same way.

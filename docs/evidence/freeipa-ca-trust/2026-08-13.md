## Real bugs found and fixed

1. **`--check` mode assert crash on the root-CA preflight (real bug, would have shipped).**
   `tasks/freeipa-ca-trust.yml`'s "read the integrated CA's issuer/subject/basicConstraints"
   task is an `ansible.builtin.command`. Ansible skips `command`/`shell` tasks under `--check`
   by default (they aren't idempotency-aware), which left `freeipa_ca_trust_ca_info` with no
   `stdout_lines` — the very next task's `assert` then crashed evaluating
   `... | select('match', '^issuer=') | first ...` against an empty sequence:
   `Error while evaluating conditional: No first item, sequence was empty.` This is exactly
   the check-mode gap the `pilot-checkmode-fresh-bootstrap-docker-gap` memory already warns
   about for a different component — the same class of bug, a second time. Fixed by adding
   `check_mode: false` to the read-only diagnostic command (it is safe to always execute for
   real, since it never mutates anything) so the live root-CA preflight gate actually works
   under `--check --diff`, not just in a real apply. Caught by the very first `--check --diff`
   dry-run against the real 3-VM group (see the "Dry-run" transcript below); fixed in one line
   before the real apply ran.
2. **(Tooling, not a playbook bug) the configured sandbox image has no `ssh` client.**
   `geerlingguy/docker-ubuntu2204-ansible:latest` (the `sandbox.image` default in
   `~/.config/pilot/config.yaml`) fails every `ansible_connection: ssh` task with
   `Unable to execute ssh command line on a controller due to: [Errno 2] No such file or
   directory: b'ssh'`. Worked around for this round by dropping `--sandbox` and running
   `ansible-playbook` directly on the host (ansible-core 2.19.2, with `community.crypto`,
   `community.general`, `ansible.posix`, `community.docker` already installed) — not a defect
   in this feature's own code, but worth flagging since every prior spec test in this repo's
   history assumed `--sandbox` worked. Also hit: `-e @~/.vault/...yaml` doesn't resolve inside
   the sandbox container (the host's `~/.vault` is never mounted in) — for this sandboxed test
   the password was passed as a literal `-e ipa_admin_password=...` instead; a real deployment
   would use `--ask-vault-pass`/`--vault-vars-file` against `pilot verify`'s own secret-aware
   runner, which is unaffected by either gap.
3. **(Environmental, not a playbook bug) the host's Harbor cache container had exited.**
   `pilot services status` reported `running=true`, but `--services local` failed closed with
   `Harbor is unreachable` because the six `pilot-harbor-dev-lite-*` containers had all
   `Exit(128)`'d (apt-cacher-ng and Pulp were still healthy). Fixed by re-running
   `pilot services up --profile dev-lite`, which restarted them; `curl .../health` returned
   `200` before retrying `vm-target up`. Noting this because `services status`'s `running=true`
   did not by itself guarantee every component was actually healthy.

subject=O=IPA.PILOT.INTERNAL, CN=Certificate Authority

### 5. C3/C4 self-skip and C5 enrollment-independence, confirmed with raw probe output

The verify run's markdown report only records "typed matcher matched", so the branching
behavior was separately confirmed with the exact spec probe commands via `vm-target exec`:

| Host | C3 (Debian branch) | C4 (RedHat branch) | C5 (enrollment-independence) |
|---|---|---|---|
| `ca-trust-ubuntu` (Ubuntu) | `trusted` | `skip` | `trust-without-enrollment` |
| `ca-trust-el` (AlmaLinux) | `skip` | `trusted` | `trust-without-enrollment` |
| `ca-trust-ipa` (AlmaLinux, is the FreeIPA server) | `skip` | `trusted` | `enrolled` |

C3/C4 each self-skip on the OS family they don't apply to (as documented in
`docs/verification/freeipa-ca-trust.md`'s intro — v2 has no runtime `targets.platforms`
filter, so the probe self-guards). C5 is genuinely enrollment-independent: both client VMs,
which never ran `freeipa-client-apply.yml` (no `/etc/ipa/default.conf`), still received and
trust the CA; `ca-trust-ipa` shows `enrolled` only because it *is* the FreeIPA server and
naturally has that file from its own install.

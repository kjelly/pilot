# freeipa-ca-trust: check mode on a fresh chain — 2026-10-01

Covers candidate `d175489` on top of `main` `09d71fa`. On a fresh chain that installs the FreeIPA server and then the CA trust baseline (`freeipa-ca-trust-apply.yml` C2, or `internal-endpoint-apply.yml` C10), check mode only simulates the server install. `/etc/ipa/ca.crt` therefore does not exist yet, and the root-CA gate in `tasks/freeipa-ca-trust.yml` failed every host's preview, so a topology test's L3 dry-run could not pass. Found by the dns tier's fresh topology test the same day.

The candidate prints why the preview stops and skips the rest of the include when check mode meets a missing CA (AGENTS.md §4.5 point 4). It does not use `meta: end_host`, because the file is shared and internal-endpoint's baseline play still previews the C9 resolver baseline after it. A real run without the CA still fails at the gate with the same message.

No spec row changes.

## Gate fires when the audit file stays empty

On the converged `g13-ipa`, the audit file was moved aside and an empty one put in its place (`mv audit audit.pilot-negtest; install -o dirsrv -g dirsrv -m 600 /dev/null audit`). 389-ds keeps writing to the file it has open, so the new `audit` stays empty. Then `freeipa-server-apply.yml --tags freeipa-audit`:

- rc=2 after 123 s, `g13-ipa failed=1` at "Gate: the 389-ds audit file is non-empty (spec C16)": "/var/log/dirsrv/slapd-IPA-PILOT-INTERNAL/audit is still empty after 120 s (Timeout when waiting for search string \S in …/audit), although audit logging is on and a directory write was made. …"
- The real file was moved back. The same run: rc=0, `changed=0`, "audit file has 1497 bytes after 0 s". `pilot verify docs/verification/freeipa-server.md`: PASS 20/20.

## Why wait_for, not stat + until

Checked locally with ansible-core 2.19.2 before writing the task: a `stat` with `until` whose retries run out prints "[ERROR]: Task failed: Action failed: Unknown error." and registers `failed=True` even with `failed_when: false`. `wait_for` with `search_regex` and `failed_when: false` returns `failed=False` and a "Timeout when waiting for search string" message, so the gate after it can decide and explain.

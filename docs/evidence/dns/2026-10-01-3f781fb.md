## Follow-up (not changed here)

- **Stale facts after recreating a VM (vm-target).** With `gathering = smart` and the 3600 s fact cache in `ansible.cfg`, a VM destroyed and recreated under the same name within an hour is served the old VM's facts (addresses, and for a different image also OS facts). `vm-target down` / `topology down` should drop the cache entries of the names they remove, in both target backends (AGENTS.md §5.1).
- **Resolver timeout when the first nameserver is unreachable.** E6b shows 5–20 s per lookup while the first tier host is blackholed, on both consumer paths. This already applies today when the first FreeIPA DNS server is unreachable. Shorter resolver options (for example `timeout:1 attempts:2`) would change the output of every `freeipa-dns-client` host and are left to the maintainer (dns.md §8).
- **SSH sessions dropped mid-task.** Six playbook runs today (plus two ad-hoc reproductions) stopped with `UNREACHABLE` "Data could not be sent to remote host": ssh exited 255 with empty stderr while the module was already running on the target (one `dnf` transaction kept going on the VM after Ansible gave up). It hit both AlmaLinux (`hostname`, `dnf`) and Ubuntu (apt framework) tasks, on reverted and on brand-new VMs, while another session on the same workstation was running Ansible against its own VMs on the same libvirt network. Every run used the shared `~/.ansible/cp/pilot-%r@%h:%p` ControlPath from `ansible.cfg` and the vm-target inventory. After switching to a private ControlPath (`ANSIBLE_SSH_ARGS=… -o ControlPath=/tmp/<run>/%C`, the way `pilot deploy` already isolates its own runs), the base chain and the internal-endpoint topology test ran without a drop — one run, so this is not proof. vm-target inventories could get a per-run or per-target ControlPath. Do not work around it with `ANSIBLE_SSH_RETRIES`: a retried task re-executes the module, which here started a second `ipa-server-install` and corrupted a `dnf` cache.
- **`freeipa-ca-trust` in check mode on a fresh chain.** `tasks/freeipa-ca-trust.yml` fails closed when FreeIPA is not installed yet, instead of ending the preview with a message (AGENTS.md §4.5 point 4). It only matters for a fresh chain that includes internal-endpoint.
- **vm-target aliases are hosts, not groups.** `RenderInventory`'s comment says each `--hosts` alias is also a single-host group, but the rendered inventory has none. A v1 spec whose targets are groups (core-infra-provider.md) then only verifies when the VM itself is named after the alias.

## 3. Containers left on an old inode

With the host files unchanged, each file was swapped for a variant with an
extra trailing newline via rename, the containers mounting it restarted, and
the original content renamed back. Every container then read a different
inode and different content than the host (`sha256sum` through
`/proc/<pid>/root`). One rerun per playbook:

| Playbook | stale mounts reported | changed tasks | afterwards |
|---|---|---|---|
| seaweedfs-s3 | pilot-seaweedfs `/etc/seaweedfs/s3.json` | container only | inode same |
| alertmanager | pilot-alertmanager-teams-proxy `/opt/teams-proxy.py`, pilot-alertmanager `/etc/alertmanager/alertmanager.yml` | both containers only | inodes same |
| dashboard | pilot-loki `/etc/loki/local-config.yaml` | container only | inode same |
| log-shipping | pilot-promtail `/etc/promtail/config.yml` | container only | inode same |
| snmp-exporter | pilot-snmp-exporter `/etc/snmp_exporter/snmp.yml` | container only | inode same |
| thanos-query | pilot-thanos-store, pilot-thanos-compact `/etc/thanos/objstore.yml` | both containers only | inodes same, store `/-/ready` 200, 0 restarts |

No render task reported `changed`, so in each case the check was what
restarted the container. Before this change every one of these runs would
have left the container on the old file. After the restarts, rerunning all
six playbooks gave `changed=0` again.

`--tags C1` on alertmanager with pilot-alertmanager stale: the check ran
(tagged `always`), pilot-alertmanager restarted, `changed=1`, inode same.

## 4. dcgm-exporter

Covered by the lint and by snmp-exporter, which passes its container name
to the check as the same kind of template (`"{{ snmp_exporter_container_name }}"`).
A `--check --diff` run with `dcgm_exporter_gpu_present` forced to true
stopped before the new tasks: the apt step failed with
`Source /etc/apt/sources.list.d/nvidia-container-toolkit.list not found`,
because check mode never adds the NVIDIA repository. That gap exists
without this change.

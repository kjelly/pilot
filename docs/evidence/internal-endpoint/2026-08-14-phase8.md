## Real bugs found and fixed

1. **`ipa host-del --updatedns=False` — `--updatedns` is a bare boolean flag, not a
   key=value option.** Confirmed live (2026-08-14):
   `ipa: error: --updatedns option does not take a value`. Worse, even the CORRECT bare
   form (`--updatedns`) would have been the WRONG choice here: it means "also blast
   every A/AAAA/SSHFP/PTR record for this host", which is broader than the
   surgical, ledger-scoped RRset removal delete step 1 already performs (spec.md
   §34/C22). Fixed by omitting the flag entirely — its default (omitted) behavior
   correctly leaves DNS untouched, since step 1 already handled the DNS side
   precisely.
2. **`docs/verification/internal-endpoint.md` C22's probe had the same
   leading-whitespace regex bug already documented (and fixed) multiple times
   elsewhere in this project** (C13's `dn:` probe in Phase 5, freeipa-dns's own
   attribute regexes) — `grep -q '^txtrecord'` anchored at absolute start never
   matches real `ipa ... --raw` output, which indents every attribute line with 2
   spaces. Caught and fixed *before* wasting a `pilot verify` attempt on it, by
   recognizing the already-known pattern rather than rediscovering it — a `pilot
   vm-target exec` dump of real `ipa dnsrecord-show ... --raw` output during this
   round's own manual verification showed the 2-space indent directly.

## Known follow-up (not fixed this round, out of scope)

- C21/C23/C24's own spec-authored verify probes remain dependent on a
  `pilot reconcile internal-endpoint` CLI wrapper that doesn't exist yet — building it
  (or rewriting these three probes to dispatch the real Ansible mechanism directly, the
  way C7/C9/C10/C27/C32 were fixed in Phases 6/7) is a reasonable follow-up, but doing so
  safely requires plumbing the required secrets (`ipa_admin_password`) through Spec v2's
  `SecretRef` mechanism rather than a plaintext env var — deferred rather than rushed.
- FreeIPA identity delete safety's "other references" check (spec.md §33) only checks
  `managedby_service` attributes on the host object; it was exercised this round only in
  the "no other references, safe to delete" path — the "leave object, emit warning"
  branch (another service still referencing the same virtual host) was not separately
  VM-tested.
- The route-ownership-migration gate (C24) was proven for a direct→reverse_proxy
  transition; the reverse_proxy→direct, target-host-A→B, and proxy-host-A→B variants
  share the identical assertion logic (comparing route_mode/route_owner) but were not
  separately VM-tested this round. The "IP change alone is NOT a migration" carve-out was
  confirmed correct by code inspection (the gate compares inventory_host names, never
  resolved IPs) rather than a live DHCP-reassignment test.
- C1-C3, C5, C8-C9, C17-C18, C21, C23-C24, C27-C32 remain Phase-1 placeholders,
  CLI-dependent, or simply out of this round's 2-VM topology (reverse_proxy rows), pending
  Phase 9 (TUI/actions/MCP) per spec.md §63's implementation order.

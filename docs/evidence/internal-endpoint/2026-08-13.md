## Real bugs found and fixed

1. **`--check` mode hard-fails `klist`/`which ipa-getcert` diagnostic tasks in C12's
   preflight (same class of bug as Phases 3/4, and the pre-existing
   `pilot-checkmode-fresh-bootstrap-docker-gap` memory).** Both are plain
   `ansible.builtin.command` read-only checks with no side effects, but Ansible skips
   `command`/`shell` tasks under `--check` by default, leaving their `register`ed result
   undefined and crashing the downstream `assert`. Fixed with `check_mode: false` on both
   tasks — they're genuinely safe to run for real even in a dry-run.
2. **`ipa host-add-managedby`/`ipa service-add-host` idempotency was wrongly guessed
   before being tested live.** The original `failed_when`/`changed_when` looked for
   `"already a managing host"` on **stderr**. A real rerun showed FreeIPA reports the
   already-delegated case as `rc=1` with the reason on **stdout**
   (`"member host: <owner>: This entry is already a member"`), not stderr, and with
   different wording than guessed. Fixed both tasks to check `stdout` for
   `"already a member"`.
3. **C13's `grep -c '^dn:'` leading-whitespace bug.** Real `ipa ... --all --raw` output
   indents every attribute line with 2 spaces (`"  dn: ..."`, not `"dn: ..."`); the
   unanchored-at-start regex never matched, so the probe reported `exists=0` despite the
   service principal genuinely existing. This is the exact same bug class already
   documented in this codebase's own memory for `freeipa-dns`. Fixed with
   `grep -c '^[[:space:]]*dn:'`.
4. **C14/C15/C16 ran on the wrong host.** All three rows inspect files/state (the
   certificate, the key, certmonger's tracking database) that live on the certificate
   **owner** host — frequently a different host than `freeipa-server`, which is what
   `targets.roles: [freeipa-server]` otherwise runs every row on. Running them per-host on
   `freeipa-server` silently inspected the wrong filesystem whenever owner != freeipa-server
   (exactly the scenario this feature's own worked example describes). Fixed by converting
   all three to `scope: aggregate` with an `ansible <owner> -i <inventory> -m shell` ad-hoc
   dispatch to the real owner host — the same pattern C9/C10 already use for the CA-trust
   and DNS-resolver baseline checks.
5. **`-e KEY=VALUE` with an unquoted space silently truncates the value — an Ansible CLI
   behavior, not a bug in this repo's code, but one that cost significant debugging time
   and is worth recording.** `getcert list` showed `post-save command: /usr/bin/touch` with
   its argument missing after the real `ipa-getcert request` task ran, even after switching
   the task from a free-form shell string to `ansible.builtin.command`'s `argv:` (a real
   Jinja-constructed list, confirmed correct via a temporary `ansible.builtin.debug: var:
   iep_getcert_request.cmd` task). Four isolated reproduction playbooks — static argv list,
   Jinja-constructed argv list, with `delegate_to`, and with the exact two-play
   `hosts:`/`delegate_to:` shape of the real file — all correctly preserved the full
   `-C` value when the reload-command variable was hardcoded in a `vars:` block. The
   difference: none of those isolated tests actually passed the value via `-e` on the
   command line the way the real `vm-target run` invocation does. Confirmed directly against
   plain `ansible-playbook` (bypassing pilot entirely):
   ```
   $ ansible-playbook p5-argv-test5.yml -i direct-inv.yaml \
       -e target_group=all -e myvar='/usr/bin/touch /etc/pilot-test/.reloaded'
   ok: [localhost] => { "myvar": "/usr/bin/touch" }
   ```
   Ansible's `-e KEY=VALUE` extra-vars parser treats a space inside an unquoted value as a
   separator between **multiple** `key=value` assignments on the same `-e` (it supports
   `-e "foo=1 bar=2"`), so `myvar=/usr/bin/touch /etc/pilot-test/.reloaded` is parsed as
   `myvar=/usr/bin/touch` plus a second, `=`-less, silently-ignored token. Fixed by quoting
   the value as a single YAML/JSON scalar so Ansible's value parser sees one mapping instead
   of two:
   ```
   $ ansible-playbook p5-argv-test5.yml -i direct-inv.yaml -e target_group=all \
       -e '{"myvar": "/usr/bin/touch /etc/pilot-test/.reloaded"}'
   ok: [localhost] => { "myvar": "/usr/bin/touch /etc/pilot-test/.reloaded" }
   ```
   Any future `vm-target run`/`topology run` invocation that passes a space-containing
   `-e` value must use this JSON-object form (or `key="quoted value"`), not bare
   `key=value with spaces`.

`which ipa-getcert` succeeds — all on the real `p5-client` host via `delegate_to`.

### 3. C15 — certmonger request, SAN, renewal hook

Real apply produced a tracked, monitored certificate:
```
$ pilot vm-target exec --name p5-client -- sudo getcert list -f /etc/pilot-test/server.crt
	status: MONITORING
	subject: CN=direct.apps.pilot.internal,O=IPA.PILOT.INTERNAL
	dns: direct.apps.pilot.internal
	principal name: HTTP/direct.apps.pilot.internal@IPA.PILOT.INTERNAL
	post-save command: /usr/bin/touch /etc/pilot-test/.reloaded
```

**Renewal hook smoke test** (spec.md §58 — "不要求測試真的等到 certificate expiry，可使用
safe resubmit/renewal test"): a real `getcert resubmit` re-triggers the certmonger
post-save event without waiting for actual expiry.
```
$ pilot vm-target exec --name p5-client -- ls -la /etc/pilot-test/.reloaded
-rw------- 1 root root 0 Aug 13 12:20 /etc/pilot-test/.reloaded

$ pilot vm-target exec --name p5-client -- sudo getcert resubmit -f /etc/pilot-test/server.crt
Resubmitting "20260813122051" to "IPA".

$ pilot vm-target exec --name p5-client -- ls -la /etc/pilot-test/.reloaded
-rw------- 1 root root 0 Aug 13 12:21 /etc/pilot-test/.reloaded
```
The marker file's mtime advanced from `12:20` to `12:21`, proving the post-save command ran
again on the resubmit event — the renewal hook fires for real, with its full argument
intact (bug 5 above).

## Failures, setup boundaries and recovery

The first timeout harness froze B without an independent thaw path. The production apply correctly failed at the **45s outer Ansible task budget** (74.782s whole apply), retaining B pending. Its SSH-based cleanup then lacked a true remote result because fresh SSH authentication itself depended on the frozen SSSD. Guest-agent process execution was unavailable under guest policy; an explicitly authorized reboot of **only B** restored it. Provider state/journal were preserved. Real remote health and same-roster retry (28.606s, only B refreshed) passed. This was a harness cleanup failure, not the accepted 30.079s helper observation.

The improved harness verified an independent PID1 90s autothaw timer before freezing. The accepted 30.079s helper failure retained B pending. The actual thaw command and kernel freezer=0 check succeeded; the first timer-cancellation observer incorrectly rejected stop rc=5 after the one-shot had fired and been garbage-collected. Read-only LoadState=not-found/nonactive verification corrected that observation, followed by SSSD-active/freezer=0 and the real identical retry. No production budgets or assertions were weakened.

The initial SIGTERM callback produced a marker but Ansible still completed with exit 0; it was correctly rejected as crash evidence. SIGKILL then produced the actual crashes above. Supplemental LDAP observers first used a lowercase API attribute and then compared raw values including bytes/comments; these failed without mutation. Read-only discovery and key-set normalization corrected the observers before accepted comparisons. Initial package metadata queried distribution-inapplicable package names; final installed ipa-client/sssd-common/sssd-ipa package queries succeeded on all targets. All unsuccessful attempts remain separate artifacts.

Client setup encountered an **existing installer variable-expansion/input boundary, not changed by this PR**, with the #137 literal admin credential. Setup used a dedicated disposable plain enrollment principal while preserving that accepted admin secret. A setup-only copy of the canonical client fixture adapted its legacy authentication transport to the accepted argv/stdin method; this was not the unmodified canonical fixture and was not used to overlay the formal identity candidate. Canonical user/sudo preconditions, fresh client dry-runs, actual DNS-enabled enrollment, full 12-row client verification and idempotency then passed. This record does not claim that unrelated client/fixture literal-secret boundaries were fixed.

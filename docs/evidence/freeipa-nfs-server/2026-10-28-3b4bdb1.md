## Vault rotation through `pilot edit --actions`

**Workspace.** A scratch pilot workspace; the real vault directory was not used:

- `.vault/main.yaml` is a 0600 copy of the sandbox vault: plaintext, eight top-level scalar keys, 59 comment
  lines.
- `.vault/` also holds a 0600 copy of the match roster under a non-default name.
- `hosts.yml` lists the two hosts. `p148e-nfs` sets `freeipa_roster_file` to that roster's absolute path, so
  the sync had to find it through the reference; the default `.vault/ipa-identity.yaml` did not exist.
- `pilot` ran with a scratch `--data-dir`.

**Scenario.**

```json
{"version": 1, "steps": [
  {"action": "set_vault_value", "file": "main.yaml", "key": "ipa_admin_password", "value_env": "<env var>"},
  {"action": "save_vault", "file": "main.yaml"}]}
```

It ran as `pilot edit --dir <workspace> --actions <scenario> --data-dir <scratch>`. Each new password was
30 characters, generated by a script and never printed. It started with `0` and contained ` #`, `: `, `"` and
`'`, but no braces, Jinja delimiters, backslash or newline. It reached `pilot` only through the environment.

### (i) Rotation

`pilot edit --actions` exited rc=0, with nothing on stdout and no `warning:` lines on stderr. The files
afterwards, compared without printing any value:

- **Vault:** `ipa_admin_password` equals the generated password. The other seven keys keep their values, and
  all 59 comment lines are kept. Five of the file's ten blank lines were dropped; this is the vault writer's
  existing yaml.v3 behaviour.
- **Roster:** `freeipa.admin.password` equals the generated password and the vault's value. Exactly one line
  of 186 changed, written as a double-quoted scalar.
- **Other files:** `hosts.yml` is byte-identical. All three files stay 0600. The roster's two lock sidecars
  appeared beside it.

The live FreeIPA admin password was not changed, so the rotated files were exercised in check mode only:

| Run | Result |
|---|---|
| Rotated vault + rotated roster, `--check --diff` | rc=0, `ok=16 changed=0 failed=0 skipped=26`. The drift gate reported `ok` |
| Negative control: original sandbox vault + rotated roster | rc=2, `ok=3 failed=1`, at the drift gate. The `ok` above therefore came from a real comparison of the YAML-hostile values as Ansible loaded them |

### (ii) Busy roster

Another process held an exclusive `flock` on `<roster>.pilot-remove.lock`, and a probe confirmed the lock was
held. A second rotation to a different generated password then exited **rc=1**, with an empty stdout. Its
stderr carried only this error, with the workspace directory replaced:

> step 2 (save_vault): `<workspace>`/.vault/main.yaml was not saved, so that it keeps matching its rosters: roster .vault/p148e-roster.yaml was not written: another pilot process holds its lock: inventory: already locked by another process

Afterwards, the sha256 of `.vault/main.yaml`, the roster and `hosts.yml` were byte-identical to before the
run. The vault still held the password from (i). `.vault/` held only the two files and their lock sidecars,
with no temp files.

## Secret check

A script counted the lines that contain any of four secrets: the vault password, the drifted roster password
and the two rotated passwords. It searched each value raw, with JSON/YAML double-quoted escaping, and with
YAML single-quoted escaping. For each rotated password it also searched both of its random 10-hex-character
segments, which survive any encoding.

**Files scanned (40):**

- every run log above, including both `pilot edit --actions` stdout/stderr pairs;
- the rows `pilot` recorded in its history database during the run window: 20 verify evidence rows,
  1 delivery run with 4 events, and 20 spec checkpoints;
- the rendered inventory, the topology file, the edit scenario and the scratch `hosts.yml`;
- both VMs' cloud-init and domain files;
- the background-task output captures.

**Result:** 0 matching lines.

**Positive controls.** Each control matched:

- the vault password, in the match roster;
- the drifted password, in a freshly generated drift roster (deleted afterwards);
- the first rotated password, in the rotated vault and roster (escaped form and both hex segments);
- both rotated passwords, in JSON-encoded and YAML single-quoted control files (deleted afterwards).

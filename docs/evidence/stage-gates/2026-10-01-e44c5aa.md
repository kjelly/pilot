## Found, not fixed here

All four are pre-existing and behave the same on main.
- freeipa-identity re-sets, on every run, the password of a user who never changed their initial password ("Set password for users that need one", `changed=1`).
- On an enrolled host where the role is not deployed yet, `--check` fails for pilot-access-gateway, pilot-access-directory and pilot-session-store: a missing keytab, or a missing unit.
- pilot-access-directory's Step 9 capability probe treats "0 hostgroups matched" (rc=1 from `ipa hostgroup-find pilot-target-`) as a failure. A full apply therefore fails until some `pilot-target-*` hostgroup exists, i.e. until gateway-scope has run.

## Redaction

Only the FreeIPA admin password came from the vault. It was copied into a temporary 0600 vars file that was deleted afterwards, and no secret value appears here. The roster, variables, binaries and run logs were per-run files outside the repository and were removed along with the VMs.

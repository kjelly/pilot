# Rollback under tag-scoped runs: the remaining twelve — 2026-10-01

Covers candidate `16d469e` on top of `main` `1cbc216`, the follow-up to [the first eight](2026-10-01-a860798.md). Twelve more apply playbooks had rescues that `--tags` skips, so a failed `--tags <row>` run did not roll back. Eight of them also had row tags that read a register or fact their tags do not select, and some of those rows always failed.

The candidate:
- tags every rescue task `always`;
- makes what the rescues read run under any tags: freeipa-nfs-server's create-once exports snapshot, freeipa-realm-replacement's tar snapshot and backup directory, and pilot-access-target-policy's read of the installed drop-in;
- fixes the prerequisite reads. `x is changed` becomes `(x | default({})) is changed`. Read-only detection runs under its readers' tags or `always`, and that includes the shared `/etc/hosts` resolver include;
- extends the prerequisite lints to the facts set inside included task files.

No spec row changes.

## Full runs and check mode

- At the candidate, every playbook that can complete on these targets ran twice, and the second run was `changed=0`: host-monitoring, log-server, audit-log-forwarding, log-shipping, snmp-exporter, freeipa-server, freeipa-nfs-server, pilot-access-target-policy, wazuh-manager, wazuh-fim.
- dcgm-exporter cannot complete without a GPU. With a stubbed `nvidia-smi`, it installs the NVIDIA container toolkit, then fails at the container step ("failed to create the automatic CDI modifier"), and the rescue removes the container. That run was rc=2 on both runs.
- freeipa-realm-replacement was not run in full, because it needs a second realm.
- `--check --diff` of each full playbook on a fresh host gave identical rc and `changed` on both sides, with `failed=0` everywhere, except freeipa-realm-replacement. On a never-enrolled host it fails on both sides ("Could not find the requested service sssd").
- Not verified: wazuh-fim's RedHat-only `update_cache` read, because there was no EL agent.

## Found, not fixed here

- **freeipa-nfs-server rolls back to the pre-role state.** The exports snapshot is taken once, before the role's first run. Any later failure restores it, so every managed share stops being exported. A full run already did this; tag-scoped runs now do too.
- **freeipa-realm-replacement's rollback restores local files but not access.** `ipa-client-install --uninstall` revokes the host keys on the old server, so the restored keytab is stale (`kinit -k` fails). The playbook's own failure message warns about this.
- **The apt framework does not recover from a stale index when the 404 is on a dependency.** The requested package was fine but a dependency (`dnsmasq-base`) returned 404. docker-apply then failed until `apt-get update` was run by hand.
- **Seven playbooks are still in `taggedPrerequisiteAllowlist`:** freeipa-client, freeipa-identity, gateway-scope, pilot-access-directory, pilot-access-gateway, pilot-session-store, seaweedfs-s3. None of them has a rescue.

## Redaction

Only the FreeIPA admin password came from the vault. It was copied into a temporary 0600 vars file that was deleted afterwards, and no secret value appears here. The topology, variables, stubs and run logs were per-run files outside the repository and were removed along with the VMs.

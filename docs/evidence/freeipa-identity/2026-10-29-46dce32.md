## Preparing the VM: an existing quirk, not part of this change

On the freshly installed server, before any roster was applied, `pilot identity
drift` failed at the probe task "List live sudo rule names". On the server,
`ipa sudorule-find --raw` with no sudo rules prints `0 Sudo Rules matched` and
exits 1, and that task has no `failed_when`. The same failure occurs on the
baseline binary. Once the roster above had created sudo rules the probe ran.
This is not changed here; a FreeIPA with no sudo rules at all still cannot be
probed.

Cases H3 to H5 are the defect a review found in the first version of the fix: pilot always passes `target_group` now (the flag value, else `freeipa-server`), so a vault key cannot retarget the probe. The earlier cases pass `--target-group freeipa-server` explicitly; H3 to H5 omit the flag. With the flag omitted and the vault key set to a group that does not exist, `8d965563` fails and `46dce32f` passes; the case with two hosts (a refusing client) is covered by the real-Ansible tests.

Cases B and C on the baseline are the defect in the issue: the vault held the
password, and the operator saw only the group-name warning, not why the probe
failed.

## Not covered by this run

- A positive drift (a live rule that differs from the compiled plan) was not
  produced; `no drift found` was observed against a server that matches the
  roster. The comparison code is unchanged by this change.
- `pilot identity drift --repair-managed` and `pilot access reconcile` were not
  run; they still read the admin password from the roster only (documented in
  the runbook).
- Roster-only probes (`pilot roster remove-*`, the capability probe) are
  unchanged and were not run.
- Exercised only by local tests (real Ansible, fake `ipa`/`kinit`), not on the VM: a vault password that is itself a failing template, the explicit `--vars-file` error cases (missing, a directory, unreadable, encrypted without a password file) and a vault value shorter than 8 characters; and the two-host `target_group` case (a refusing client next to the server).
- The local test suites (`go test ./...`, `go test -race ./...`,
  `make playbook-lint`) are recorded in the pull request, not here.

## Redaction

The VM address, SSH key path, workspace paths and the throwaway sandbox
password are omitted. The secret scan covered stdout and stderr of every run in
the tables above; it found the password in none of them.

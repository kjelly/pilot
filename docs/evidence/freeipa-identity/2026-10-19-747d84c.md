This proves those mutation commands were not invoked by these tasks. No new server-side API-call count or performance number is claimed. Profile reconciliation and other unrelated calls still run.

A final full `--check --diff` used the opposite account/direct-membership declaration against the final live state: `ok=59 changed=0 failed=0`. Independent LDAP state after that preview equals the pre-check state. Thus preview did not enable/disable accounts or revoke direct memberships.

The independent oracle initially required literal LDAP `nsAccountLock: FALSE` for an enabled newly-created account and failed on its absent attribute. That failed artifact is retained. Same-target `ipa user-show` then confirmed absent LDAP lock = `Account disabled: False`, while the disabled control has literal `TRUE` and reports `True`. The oracle normalizes absent lock to unlocked, rejects LDAP command errors/nonexistent DNs, and then validates the declared states. The successful matrix resumes at readback/idempotency; the fresh apply was not relabeled or rerun as fresh. Native exec assertions require an explicit success marker; the outer `vm-target exec` exit code alone does not establish remote success.

# Password resets follow the roster schema (2026-10-15)

Spec: `docs/verification/freeipa-identity.md` v1.12 §7.4; playbook: `playbooks/apply/freeipa-identity-apply.yml`; schema: `freeipa-config.md` §6.4; tests: `internal/spec/freeipa_identity_password_regression_test.go`, `internal/inventory/roster_user_password_test.go`.

Before this change the password task ran `ipa passwd` when `force_password or needs_reset`. It reset every `force_change: true` user on every run, including users who had changed their own password, reset every user still pending their first change, and never read `password.preserve_existing`. The candidate sets a password only for an account with no Kerberos key, or when `preserve_existing: false` asks for a reset and the user is no longer on the last reset's password. A failed `ipa user-show` now fails the run before any password is set.

## Captures for the tests

`internal/spec/testdata/freeipa-user-show-raw-*.txt` are `ipa user-show <user> --all --raw` stdout from the same server: an account with no password (`has_password: FALSE`, no `krbLastPwdChange`), right after `ipa passwd` (both attributes equal), after the user's own change under `maxlife=90`, and under `maxlife=0` (no `krbPasswordExpiration`). A user that does not exist gives rc=2 and `ipa: ERROR: <user>: user not found` on stderr; without a Kerberos ticket every `ipa` command gives rc=1 and `ipa: ERROR: did not receive Kerberos credentials`. (The first version of this record said rc=1 for a missing user; that capture had run after the admin ticket was destroyed.)

## Tests

- `TestRegression_IdentityPasswordResetFollowsRosterSchema` runs the playbook's lookup, decision, gate and password tasks, extracted by name, on localhost, with `cat` of the captures in place of `ipa user-show` and a debug task in place of `ipa passwd`. With the old "`force_change` always resets" condition put back, it fails with four more users reset (`pending-forced`, `changed-forced`, `reset-done`, `legacy-reset-done`); with a missing `krbPasswordExpiration` read as "still on the reset password", it fails on `nomax-reset`.
- `TestRegression_IdentityPasswordLookupFailureSetsNothing`: a lookup that fails stops the run and no password is set; it fails if the lookup result is ignored.
- `TestRegression_IdentityPasswordCheckModeSetsNothing`: in check mode nothing is decided and nothing fails.
- `TestRegression_IdentityPasswordFlagsMustBeBooleans` and `TestValidateRoster_UserPasswordFlags*`: the playbook gate and the Go validator reject a null or string `force_change`/`preserve_existing`; the gate test fails without the new checks.

## Found while testing

FreeIPA accepts an administrator's `ipa passwd` with a password shorter than the policy minimum (6 characters against `Min length: 8`: rc=0). The password task's `failed_when: false` hides real failures: for a roster user that was removed outside Pilot with `ipa user-del --preserve`, `ipa passwd` fails with rc=2 (`no matching entry found`) and the task reports `ok`. That is issue #102; this change does not alter that task's `failed_when`.

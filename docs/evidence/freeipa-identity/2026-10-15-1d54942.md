# ipa failures are no longer read as success or absence (2026-10-15)

Issue #102. Spec: `docs/verification/freeipa-identity.md` v1.13; playbook: `playbooks/apply/freeipa-identity-apply.yml`; tests: `internal/spec/freeipa_identity_ipa_failures_regression_test.go` (fixtures `internal/spec/testdata/freeipa-ipa-cli/`).

Before this change several tasks ignored `ipa` failures where a failure changes what the run does:

- `ipa passwd` failing was reported as `ok` (`failed_when: false` under `no_log`), and the account kept no password.
- The user, group, hostgroup, netgroup, HBAC and sudo membership lookups read a failure as "no members", so stale access was silently kept.
- Three existence checks did not tell "not found" from other errors: the group lookup before `group-del` (an error let `group-del` run without the history marker), canonical hosts, and group password policies.
- When a roster host was removed, an error from `host-show` or `service-find` skipped the deletion gates, but `host-del` ran anyway.
- The HBAC lockdown rescue always said `allow_all` was re-enabled.

## Captures

`internal/spec/testdata/freeipa-ipa-cli/` holds stdout, stderr and exit code of `ipa` commands run on the same server. Every `<obj>-show` of a missing object exits 2 with `ipa: ERROR: <name>: <type> not found` (user, group, host, host group, netgroup, HBAC rule, sudo rule, password policy). `ipa passwd` on a preserved or missing user exits 2 with `ipa: ERROR: no matching entry found`. `service-find --man-by-hosts=` with no match exits 1 and prints `Number of entries returned 0`. Without a Kerberos ticket every command exits 1 with `ipa: ERROR: did not receive Kerberos credentials`, which the tests use as the "other error". An administrator's `ipa passwd` with a password shorter than the policy minimum (6 against 8) exits 0, so the policy is not a failure trigger.

## Tests

`freeipa_identity_ipa_failures_regression_test.go` runs the playbook's own tasks, extracted by name, on localhost with a fake `ipa` first on `PATH`. The fake replays the captures and records every call. It covers the password gate (one user failing, and all accepted), the canonical group membership lookup, the group lookup before `group-del`, the canonical host lookup, the password-policy lookup, the absent-host lookups before `host-del`, and both rollback outcomes. Each test failed with its fix reverted: `failed_when: false` put back on the canonical group, group-before-delete, canonical host, password-policy and both absent-host lookups; the password gate made to always pass; the old fixed rollback message restored. Putting `failed_when: false` back on the hostgroup lookup fails the allowlist test.

`TestRegression_IdentityFailedWhenFalseIsAllowlisted` lists every task in the playbook still marked `failed_when: false`, with the reason it is safe; a new one fails the test. Four remain as known gaps: the two decommission DNS lookups (#105) and the HBAC/sudo reference queries, which never match (#104).

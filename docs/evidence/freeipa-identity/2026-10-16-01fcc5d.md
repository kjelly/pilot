# Reruns skip user and group calls known to be no-ops (2026-10-16)

Plan `docs/superpowers/plans/2026-10-15-freeipa-go-ssh-reconcile.md`, Phase −1 optional item, extended to groups. Playbook: `playbooks/apply/freeipa-identity-apply.yml`. Tests: `internal/spec/freeipa_identity_user_listing_regression_test.go` and `internal/spec/freeipa_identity_group_noop_regression_test.go`. Spec: `docs/verification/freeipa-identity.md` v1.15. Runbook: `docs/runbooks/freeipa-identity.md` §5.

Before this change, every rerun called `user-add`, `user-enable`/`-disable`, `group-add` and `group-add-member` for every user, group and direct member in the roster, even when FreeIPA already matched the roster. The run now reads `ipa user-find --pkey-only` (all users, and the disabled ones), `ipa group-find --pkey-only`, and the direct members the membership lookup already reads. It skips the calls those reads show would change nothing.

## Captures and tests

`internal/spec/testdata/freeipa-ipa-cli/` holds real FreeIPA 4.13.4 outputs:
- `user-find`/`group-find --pkey-only`: complete, truncated (`--sizelimit=3`, stderr `ipa: WARNING: Search result has been truncated`), in German, and with no disabled users (exit 1, `Number of entries returned 0`);
- `group-show --all` with direct, nested and indirect members;
- the `user-add`, `user-enable`/`disable`, `group-add` and `group-add-member` answers.

The `user-find` and `group-find` `--help` options are added to `freeipa-cli-options.txt`.

The tests run the playbook's own tasks on localhost with a fake `ipa` that replays those captures and fails any other call. They check:
- which calls each case makes, including a roster name in another case and an indirect member that must still be added directly;
- `--check`;
- that a missing ticket, a truncated listing or a German listing stops the run before any write.

Putting back each of the 11 changed behaviours one at a time makes at least one test fail.

# Removing a user's last SSH key revokes it (2026-10-15)

## Captures and tests

- `internal/spec/testdata/freeipa-ssh-keys/` holds the real outputs of `ipa user-mod <user> --sshpubkey=`:
  - for a user with a key: exit 0, `Modified user "<user>"`;
  - for a user without one: exit 1, `ipa: ERROR: no modifications to be performed`. The task already tolerates this.
- The tests run the playbook's own task on localhost with a fake `ipa` that replays those captures and records each call. They check:
  - a listed key, an emptied list and a never-keyed user each produce the expected call;
  - a user without `ssh_keys` produces none;
  - clearing a never-keyed user stays a no-op.

  With the old task the first test fails, because a bare `user-mod` call has no recorded answer and the fake rejects it.

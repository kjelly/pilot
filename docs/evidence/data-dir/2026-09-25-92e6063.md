## The problem

| Resolver | Used by | `--data-dir` | `PILOT_DATA_DIR` | config `data_dir` |
|---|---|---|---|---|
| `resolvePilotDataDir()` | deploy, verify, spec, webhooks, host decommission | yes | yes | yes |
| `loadConfig().DataDir` | services, doctor | yes | **no** | yes |
| `resolveDataDir()` | vm-target, docker-target, access grants/breakglass, identity drift | yes | **no** | **no** |

`vm-target run` and `vm-target verify` also turn off cobra's flag parsing, so
the root `--data-dir` never reached them at all.

## Migration notes

- Nothing moves on upgrade, and nothing is deleted. A command whose own
  state file is only in the old location prints the notice with `file`,
  `found_in` and `data_dir`; moving the file, or passing
  `--data-dir <found_in>`, keeps managing it.
- The old locations were `~/.local/share/pilot` for `vm-targets.json`,
  `docker-targets.json`, `breakglass-activations.json` and
  `auth-policy-hosts.json`, and `data_dir` (or the default) for
  `services.json`. With `--data-dir` set nothing moved, so there is no
  notice.
- While old and new pilot binaries run side by side, an old one takes the
  network lock next to its state json and a new one in the VM directory, so
  the two do not exclude each other.

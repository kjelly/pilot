The regression rejected both original sims at baseline `acd9a38` for lacking a readiness check.
The behavior tests execute the actual playbooks with deterministic transport/identity
processes; the target runs above additionally exercise real SSH, sudo and SSSD.

The readiness query checks effective command permission, not NOPASSWD or the identity
of a cached rule. The subsequent SSH `sudo -n` assertions still enforce noninteractive
allow/deny behavior. An already cached rule cannot prove that this fixture run has
propagated, and revoked-rule freshness remains outside this gate's guarantee.

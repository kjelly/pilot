not appear in them.

## 4. Key digests from the real FreeIPA classes

This check ran the candidate's observer script on the server with `/usr/bin/python3`. That interpreter
imported `ipalib` and `ipapython.ssh` from `/usr/lib/python3.9/site-packages`. Neither the drift probe nor its
tasks set `PYTHONPATH`.

The input was one managed user holding two keys. One key had options `no-pty,from="10.0.0.0/8"` and a comment;
FreeIPA stored those options sorted, as `from="10.0.0.0/8",no-pty`. The other key had a comment only.

The observer's two live digests equalled the SHA-256 of each `ipaSshPubKey` value from `ipa user-show --all
--raw`, after base64-decoding the raw attribute. Drift then reported `user_ssh_keys` / update, apply changed=1,
and drift returned exit 3.

## Findings outside this PR (the base behaves the same)

- **`--repair-managed` with a templated roster admin password.** The capability probe gets only the roster, not
  `--vars-file`. When the roster's `freeipa.admin.password` is a template of the vault value, the repair stops
  with "capability probe failed … exited 2". The base binary fails identically. The repair succeeded with a
  roster copy holding the literal password, which is the documented requirement ("the repair step itself still
  reads the admin password from the roster only").
- **Initial password visible in apply `-v` output.** Apply at `-v` prints the roster's initial password in the
  loop-item output of seven tasks: "Select active identity objects", "Ensure IPA users exist", "Reconcile user
  first/last names", "Reconcile canonical account enabled state", "Set SSH public keys…", "Look up current user
  group memberships" and "Compute stale group memberships to remove". Base `fdb6f03e` prints it in the same
  seven tasks. Default verbosity prints nothing.
- **Known, already recorded:** an option-prefixed key in the roster still fails apply at "Prepare durable SSH key
  cache work". It was not re-run here.

## Not exercised, and limits

- **None of the observer's own failure classes was triggered live** (`bad_input`, `ipalib_unavailable`,
  `desired_key_invalid`, `kerberos`, `rpc_failed`, `incomplete_search`, `account_state_missing`,
  `invalid_response`), nor the mapping of real ipalib exception names to `kerberos`/`rpc_failed`. They are
  covered only by the fake-ipalib, real-Ansible tests. The live failure paths were the roster pre-gate (8a) and
  existing probe tasks (8b, 8c): the observer runs after the probe's existing `ipa` CLI tasks, with the same
  private cache and the same `cli` context, so every server or credential failure that could be induced without
  editing repository files fails an earlier task first. Every observer failure path fails closed with a fixed label.
- **One FreeIPA server.** The two-alias inventory shows `run_once` behaviour, but on one host, not two servers.
- **No hosts, hostgroups, netgroups, HBAC/sudo attachments or password actions**, which are outside Phase 1.
- **No stage users.**
- **A raw LDAP key written in a spelling FreeIPA would normalize differently** was not constructed.

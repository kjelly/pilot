## Review findings and fixes

**P2-1: a success answer missing its fields was taken as a valid result.**

Before, these were all accepted:
- `user_mod` answered `{}`: success;
- a find answered `{"result":{}}` or `{"result":null}`: an empty set;
- a find without `truncated`: a complete read.

Now:
- The envelope must carry `error` (null) and a `result` object, and an error object must have a name.
- Every allowlisted command but `ping` must carry a non-null inner `result`, as every captured answer does.
- A find needs `count`, `truncated` and `result`, all present, non-null and of the right type, with `count` equal to the entries and no null entry.
- A member result needs `completed` and `failed.member`, with no null list.
- Anything else is `ErrIncompleteResponse`. For a single write it is an `OutcomeUnknownError` counted in `Stats.Unknown`; for a read it is a plain error.
- A real empty find is still an empty set. This was newly captured: `user_find`/`group_find` with no match answer `count: 0`, `truncated: false`, `result: []`.

**P2-2: a batch with a write that could not be decoded was a plain error.**

A batch that was sent, contained a write, and was answered with a result that does not account for every command is now an `OutcomeUnknownError` with the cause kept, counted in `Stats.Unknown`. That covers:
- a wrong count;
- missing `results`;
- a result that is not an object;
- an item without a non-null `result`;
- a failed item without `error_name`.

Read-only batches keep plain errors.

The "wrong count" case uses the real answer to an empty batch (`count: 0, results: []`, newly captured) given to a batch of one. The other malformed bodies are fault injection: FreeIPA was not seen sending them, and the tests say so.

**Same-class scan** (AGENTS.md §5.10) over every decode path in the package:
- `Logout` reads only the envelope, so its check is the envelope check above. It now has its own test.
- `Ping` already failed when `summary` was missing or did not match.
- Login already required HTTP 200 and the session cookie.

**Tests:**
- `TestIncompleteAnswersAreNotSuccess`: 9 bodies, each as a write and as a read.
- `TestFindRequiresACompleteAnswer`: a real empty answer, and 8 injected cases.
- `TestBatchAnswersThatCannotBeConfirmed`: 6 cases, each as a write batch and as a read batch.
- `TestMemberResultsMustAccountForEveryField`.
- `TestLogoutNeedsACompleteAnswer`.

**Mutation checks.** Removed one at a time, each check made a test fail:
- the envelope result check;
- the error-name check;
- the inner `result` check;
- the write-to-unknown mapping in `Call`;
- the find field checks;
- the null-entry check;
- the write-batch-to-unknown mapping;
- the batch count/results checks;
- the failed-item name check;
- the batch item `result` check;
- the member `failed.member` check;
- the null member list check.

Two removals first failed nothing:
- "a batch item is an object" was redundant (decoding already rejects it) and was removed;
- the envelope check is the only guard for `Logout`, which then got its test.

## What the first live runs found (fixed before the candidate, with tests)

- **`hbactest` was refused by the client.** Its answer has `value` and `summary` and no inner `result`; the client required `result` of every command but ping, so the lockdown's proof failed as an incomplete response and the lockdown stopped at H8 with `allow_all` untouched. The first apply that reached it (a lab run before the driver) had seven writes in and no lockdown. Fixed in `7d94d7c7`: `hbactest` requires `value`; the eight HBAC reads' captured answers go through the whole client in a test, and an answer without a value is still refused.
- **A converged stage printed that the read-back disagreed with the roster** (it had not read back, having nothing to write). Fixed in `7d94d7c7`.
- Driver mistakes found while it was developed, all in the arms and not in the engine: a count of the server's `user_mod` log lines taken for the Go phase's writes (the identity playbook sets the users' ssh keys on every run, 4 `user_mod` commands, so the Go phase's own statistics are asserted instead); a deleted user still listed in a group (the users and groups plan refuses that before the HBAC stage); a rule's `usercat=all` set on a rule that has users (FreeIPA refuses it); a client stopped before the run (pilot's availability check refuses that with the required host `cli1` unreachable, exit 1, before anything is applied, which is also a result: it is not the second-run failure). One development run of H9 ended at the first ssh because the control directory the harness had just recreated was gone; it did not recur in the two later runs of H9, and the diagnostics stay in the arm's facts.

## Not covered

- Any production server or production-sized roster: the lab has a handful of rules (K9, the read cost at scale, is still not measured), and one client. The settlement's cost with many clients is not measured; with one client the full converged run took 80 s against the Ansible engine's 121 s in one run each, which is not a benchmark.
- The apply-time blocked HBAC stage (the preview accepts, the re-read after the playbook finds a reference gone) was not made to happen live; it is covered by the fake server's tests only. The roster validator and the preview refuse every unresolved reference this lab could make before the stage runs.
- The transaction's own `--tags`: the second playbook run adds `--tags client-cache` after the transaction's arguments; if a future identity transaction passes tags, the two are a union. No guard.
- #394 (a template or inline `!vault` in `password.initial` is blocked for a new user in the Go engine) still applies to a roster that uses one.
- The Ansible engine's own HBAC tasks are exercised as the cross-check of H0 and H1; the Phase 2 arms were not rerun.

## Live driver (`TestLiveGoPreviewDriver`)

How an earlier candidate was run, from a clean local clone of it (secrets elided):
```
PILOT_IDENTITY_ENGINE_LIVE_VM=pwfix-ipa PILOT_IDENTITY_ENGINE_LIVE_WORKSPACE=<workspace> \
PILOT_IDENTITY_ENGINE_LIVE_DRIFT_USER=p1live-ann PILOT_IDENTITY_ENGINE_LIVE_DRIFT_GROUP=team-p1live \
PILOT_FREEIPA_LIVE_SSH=root@192.168.122.3 PILOT_FREEIPA_LIVE_SSH_KEY=<key> \
PILOT_FREEIPA_LIVE_SSH_OPTS=StrictHostKeyChecking=no,UserKnownHostsFile=/dev/null \
ANSIBLE_VAULT_PASSWORD_FILE=<file> IPA_ADMIN_PASSWORD=<lab password> \
go test -count=1 -timeout 90m -run TestLiveGoPreviewDriver -v ./internal/identityreconcile/
```

The workspace was a scratch one under the repository's ignored `tmp/`: `hosts.yml` (one host, role `freeipa-server`, absolute `freeipa_roster_file`) rendered with `pilot inventory generate`; `.vault/main.yaml` and the roster encrypted with `ansible-vault`, the vault password read by Ansible from `ANSIBLE_VAULT_PASSWORD_FILE` (the spec §3 ambient mode). Roster: schema 3, users `p1live-ann`, `p1live-ben` (display name, email, shell), `p1live-cat` (`state: disabled`); groups `team-p1live`, `role-p1live` (nested `team-p1live`), `data-p1live` (non-POSIX). The admin password was a lab-only one set on the VM as root over ldapi, kept in a mode-0600 file outside the repository and passed to the test process's environment; no operational vault was used.

Each preview sends 5 HTTP requests (login, `ping`, `user_find`, preserved `user_find`, `group_find`; logout is not counted), 4 reads, 0 writes, 0 re-logins, 0 read retries. Before and after each preview the driver reads the size of `/var/log/httpd/error_log` and looks for any `user_add`/`user_mod`/`user_del`/`user_enable`/`user_disable`/`passwd`/`group_add`/`group_mod`/`group_del`/`group_add_member`/`group_remove_member` call in the part added during the preview. At the end the test rolls the VM back to the pre-test snapshot; both snapshots are then deleted.

## Captures K1–K4 (spec §9)

Taken on 2026-11-05 with a throwaway capture tool through the same SSH tunnel, as admin, on `pwfix-ipa` (FreeIPA 4.13.4, API 2.257). They are facts about that FreeIPA version, not about a candidate. The fixtures are in `internal/freeiparpc/testdata/` and the facts are locked by `internal/freeiparpc/find_limits_fixtures_test.go` and the observer tests in `internal/identityreconcile`. All `p1-*` test objects were deleted afterwards (0 users, 0 preserved users, 0 groups left).

| # | Result |
|---|---|
| K1 | A plain `user_find` never lists a preserved user; `preserved: true` lists only preserved users, each `preserved: true`, `nsaccountlock: true`, without `memberof_group` |
| K2 | An external group's object classes are the non-POSIX set plus `ipaexternalgroup`; no `gidnumber`. Phase 1 still treats it as unrecognized |
| K3 | With 151 users and 101 groups: `ipasearchrecordslimit=10` (FreeIPA's minimum) does not limit `sizelimit=0` reads; without `sizelimit` the read stops at 10 with `truncated: true`. `nsslapd-sizelimit=3`, then `nsslapd-lookthroughlimit=3`: `user_find` answers `truncated: true`, `group_find` fails with `SizeLimitExceeded` / `AdminLimitExceeded`. No read was shortened silently. All three limits were restored (100, 100000, 100000) and read back |
| K4 | The unfiltered `user_find --all`: 138 users, all parsed by the observer; `admin` is in `admins` and `trust admins` and has no `givenname` |

The preserved-user capture first held the NT hash of its `p1-*` capture account. Review caught it: the value is now a placeholder, `TestCapturedFixturesCarryNoSecrets` fails for any fixture that holds a secret-bearing attribute (`ipanthash`, `userpassword`, `krbprincipalkey`, `ipatokenotpkey`) with anything else, and the hash remains in the history of this branch. The account was deleted with the other `p1-*` objects.

## Environment changes

- **Admin password**: the VM's earlier lab password was replaced with a new random one (`ldappasswd` as root over ldapi, read from a file, never on a command line). Earlier lab credentials for this VM no longer work.
- **VM memory**: raised from 4096 MiB to 6144 MiB. With 4096 MiB the guest reports 3911 MiB, below the `freeipa-server` contract minimum of 4096, and `pilot reconcile --force` stops at the delivery resource check before applying the required `freeipa-server` dependency.

### sshd refusing forwarding

`AllowTcpForwarding no` was set in a drop-in, sshd reloaded (`sshd -T`: `allowtcpforwarding no`), and the live tests ran with `PILOT_FREEIPA_LIVE_EXPECT=forwarding-denied`:
- The tunnel test got `ErrForwardingDenied`: ssh exit 255, `channel 0: open failed: administratively prohibited: open failed; stdio forwarding failed`.
- Login failed as `not sent: TLS handshake with ipa1.ipa.pilot.internal: sshd refused the TCP forwarding …`, so no password left.

The drop-in was removed afterwards (`allowtcpforwarding yes`).

## Captures and unit tests

- `internal/freeiparpc/testdata/` holds real responses. They cover:
  - login: OK, invalid password, expired password, `json` without a session;
  - commands: ping, show, add, mod, enable/disable, and their errors (`NotFound`, `DuplicateEntry`, `EmptyModlist`, `AlreadyActive`, `AlreadyInactive`, `ACIError`, `CommandError`);
  - membership results;
  - a truncated find and a batch with failed items;
  - `session_logout`, and the 401 that follows it.

  The cookie's attributes (`path=/ipa;httponly;secure;SameSite=strict`) are recorded without its value.
- `internal/sshdial/testdata/` holds OpenSSH's own messages for:
  - `AllowTcpForwarding no`, `DisableForwarding yes`, and `PermitOpen` without the destination;
  - a refused destination;
  - a failed authentication.

  It also holds the VM's public IPA CA.
- The unit tests replay these against an `httptest` TLS server and a fake `ssh`.
- Mutation checks: each test failed when its behaviour was removed. One check was missed at first, because a test replaced the transport's dialer directly; the test was fixed, and the mutation then failed it. The behaviours:
  - re-login on 401;
  - writes not re-sent after a lost answer;
  - the truncation check;
  - per-item batch errors;
  - the allowlist;
  - dial failures marked "not sent";
  - the member count check;
  - the API version in every command;
  - the cookie scope.

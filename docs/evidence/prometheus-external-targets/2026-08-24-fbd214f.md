## 6. Real bugs found and fixed on this round (not guessable from the YAML alone)

**Bug 1 — `selectattr('enabled', 'default', true)` is not valid Jinja.** `'default'` is a
filter, not a `selectattr` test name; every use failed at apply time with `The filter
plugin 'ansible.builtin.selectattr' failed: No test named 'default'.` Fixed by
normalizing `enabled` into a real boolean on every target up front (a `{'enabled': true}
| combine(item)` loop-accumulation, base-then-override — not the reverse, which would
have forced every target enabled regardless of an explicit `false`), then using plain
`selectattr('enabled')` everywhere downstream.

**Bug 2 — C3's regex didn't match `to_nice_yaml`'s actual key order.** Same class of bug
`prometheus.md`'s own C13 note already documents: `to_nice_yaml` alphabetizes dict keys,
so `file_sd_configs` (alphabetically before `job_name`/`metrics_path`/`scheme`) becomes
the scrape job's FIRST key, rendering as `- file_sd_configs:` (a YAML list-item dash)
rather than the bare `  file_sd_configs:` the original `^[[:space:]]*file_sd_configs:`
regex assumed. Fixed to `^[[:space:]]*-?[[:space:]]*file_sd_configs:`, re-verified PASS.

**Bug 3 (repository-level, pre-existing, not caused by this feature) — `prometheus.md`'s
own `pilot verify` resolution fails on a plain single-VM `vm-target`.** The spec's §1
table declares inventory group `prometheus`; `vm-target`'s rendered inventory only ever
emits a flat `all.hosts.<name>` with no such group, and the expected-host resolver
(`internal/tools/expected_hosts.go`) has no wired escape hatch (`TargetGroupOverride` is
referenced only in that package's own tests, never set to `true` by any production
caller) — `pilot verify docs/verification/prometheus.md` on a bare `vm-target verify
--name <x>` errors with `spec targets matched zero inventory hosts and no target_group
override was provided`. Worked around for this evidence run by hand-adding a
`children: {prometheus: {hosts: {<name>: null}}}` block to a copy of the rendered
inventory and calling `pilot verify` directly with `-i <patched-inventory> -l <name>`.
Not fixed here — orthogonal to this feature, flagged for a separate follow-up.

## Real bugs found and fixed

1. **`--check` mode hard-fails `ansible.builtin.service` on a genuinely fresh host (same class
   of bug as Phase 3's CA-trust preflight, and the pre-existing
   `pilot-checkmode-fresh-bootstrap-docker-gap` memory).** `apt`/`dnf` correctly *simulate* the
   nginx install under `--check` without actually installing it, so the immediately-following
   `ansible.builtin.service: {state: started, enabled: true}` task has no real `nginx.service`
   to act on and fails hard (`Could not find the requested service nginx: host`) instead of
   predicting a change. Fixed with `when: not ansible_check_mode`, same as the two `reload
   nginx` handler tasks added later in this round (they hit the identical failure once a
   `notify` first fired against a fresh host).
2. **C4's original probe was too weak — a real functional gap, not just a check-mode
   artifact.** The spec's original C4 row only checked for the *absence* of
   `/etc/nginx/sites-enabled/default` and `/etc/nginx/conf.d/default.conf`. On AlmaLinux 9,
   nginx's own vendor `/etc/nginx/nginx.conf` bakes an **unmarked, inline** `server { listen
   80; server_name _; }` block directly into the `http{}` section — there is no
   `conf.d/default.conf` file at all, so the original probe would have reported PASS while
   that inline block was still the active default, fully intercepting any unmatched Host
   header. Confirmed with a real `curl -H 'Host: pilot-c4-probe.invalid'` before any fix
   landed. Fixed two ways:
   - The apply playbook now claims the `default_server` slot explicitly via a new
     `/etc/nginx/conf.d/pilot-reverse-proxy-default.conf` (`return 444`) on **both** distros —
     nginx always prefers an explicit `default_server` over an implicit first-block default
     regardless of definition order, so this wins without ever touching vendor `nginx.conf`.
   - `docs/verification/reverse-proxy.md`'s C4 row now does the same real functional check
     (unmatched Host header must get no response) instead of checking file absence.
3. **(Minor, self-inflicted) `server_name _;` collision.** The first version of the
   `default_server` catch-all also declared `server_name _;`, which collides with
   AlmaLinux's own vendor block of the same name — `nginx -t` still passed, but emitted
   `conflicting server name "_" ... ignored` on every run. Fixed by dropping `server_name`
   from the catch-all entirely; `default_server` alone is sufficient and doesn't need a name
   to match on. Confirmed `nginx -t` is warning-free after the fix.

Each new row command was run against that reproduction before it went into

Sidecar's metrics endpoint.

Downsampling and query behaviour, 45 days of synthetic 15s samples, one
Compactor pass per run with raw 7d / 5m 30d / 1h 90d (steady state after
three runs: raw blocks to 18.1d old, 5m to 32.1d, 1h to 45d), then Store +
Query:

| Data age (blocks present) | no param | `auto`, step 60s | `auto`, step 2h | `1h` |
|---|---|---|---|---|
| 10d (raw+5m+1h) | 361 / 85 | 361 | 85 | 361 / 85 |
| 25d (5m+1h) | 0 / 0 | 0 | 85 | 361 / 85 |
| 40d (1h) | 0 / 0 | 0 | 0 | 361 / 85 |

(Points returned for `exp_gauge`; "a / b" = step 60s over 6h / step 2h over
7d.) A range query without `max_source_resolution` reads raw blocks only.
`rate(x[5m])` over downsampled data returns nothing; `rate(x[3h])` does.
Restarting Query with `--query.auto-downsampling` and no parameter: 25d
ago, step 2h → 85 points; step 60s → 0; instant query at 25d ago → 0 series
(instant queries still read raw only).

## 1. The review findings, reproduced before the fix

### P1: raw-only blocks lost with raw 30d

`scripts/thanos-retention-behavior-test.sh` uploads synthetic blocks to a
FILESYSTEM bucket and runs one Compactor iteration with the playbook's
retention flags. A block marked for deletion counts as deleted. The script
covers four sites:

- a site that ran for 2h;
- a site that stopped, whose last 26h stay raw-only because the span is under 40h;
- a site that changed its label (old and new label);
- a 95-day-old site that must be deleted.

With the old default raw 30d (`RETENTION_RAW=30d`):

```
Compactor retention: raw=30d 5m=90d 1h=90d (thanosio/thanos:v0.36.1, promtool from prom/prometheus:v2.53.0)
site         data                   blocks left (raw/5m/1h, marked)    want     result
short-lived  45.1d ago, 2h          0/0/0, 1 marked                    kept     FAIL: lost
stopped      45.2d ago, 74h         0/2/0, 46 marked                   kept     FAIL: lost
relabel-old  45.9d ago, 58h         0/2/0, 36 marked                   kept     FAIL: lost
relabel-new  43.9d ago, 48h         0/0/0, 30 marked                   kept     FAIL: lost
expired      95.1d ago, 2h          0/0/0, 1 marked                    deleted  ok
```

With the new defaults (90d/90d/90d, read from the playbook by the script):

```
Compactor retention: raw=90d 5m=90d 1h=90d (thanosio/thanos:v0.36.1, promtool from prom/prometheus:v2.53.0)
site         data                   blocks left (raw/5m/1h, marked)    want     result
short-lived  45.1d ago, 2h          1/0/0, 0 marked                    kept     ok
stopped      45.2d ago, 74h         8/2/0, 38 marked                   kept     ok
relabel-old  45.9d ago, 58h         6/2/0, 30 marked                   kept     ok
relabel-new  43.9d ago, 48h         6/0/0, 24 marked                   kept     ok
expired      95.1d ago, 2h          0/0/0, 1 marked                    deleted  ok
```

The stopped and relabelled sites show what the review predicted: their 5m
blocks cover only the first 48h, so raw 30d deletes the rest with nothing
left.

### P2: C8/C22 read every `site:` key

The new `internal/spec/prometheus_site_selector_behavior_test.go` runs the
C8 and C22 commands as written in the spec. It uses the prometheus.yml
rendered on `rv-site` (§5), with a fake `docker` that parses `--selector`
the way Thanos does (`strconv.Unquote`, cmd/thanos/config.go:280).

Run against the `c52884e` rows (same tree otherwise), 3 of the 4 tests fail:

```
C22: pass=false selector=["site=\"\"review-site\"\nreview-site\""]   (SNMP render, recent block)
C22: pass=false selector=["site=\"\"a \\\"b\\\" \\\\ c é\"\nreview-site\""]
no external_labels: C8 pass=true, C22 pass=true selector=["site=\"review-site\""]
unquoted site:      C8 pass=true
empty site:         C8 pass=true
```

Without `external_labels`, the old C22 passed on the snmp job's label. All
four tests pass on A, B and C.

were compared byte for byte with the captured file. C22 then passes

form: `tools bucket inspect --selector='site="a \"b\" \\ c \u00e9"'` listed
both blocks uploaded with the label `a "b" \ c é`, and a near-miss selector
(`e` for `é`) listed none.

## 5. Fixture provenance

`internal/spec/testdata/prometheus-site-selector/prometheus-snmp.yml` was
captured from `/etc/pilot/prometheus/prometheus.yml` on `rv-site`. The
capture came from a dev apply of the working tree on 07:40 UTC, before A
was frozen. The VMs were then destroyed and re-provisioned for §3. The
render on the fresh candidate-A host (captured 08:09 UTC) is byte-identical
to the fixture. `bucket-inspect.tsv` is
`thanos tools bucket inspect --output=tsv` output from
`thanosio/thanos:v0.36.1` against a local FILESYSTEM bucket holding two
blocks, with a label value that contains quotes and a backslash.
